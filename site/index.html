它解决什么

八件事：前六件是每天都会碰到的，后两件是敢把历史交给它的前提。

shortcut ⌘⇧V → 面板 ⏎ 粘回原应用 ⌘1-9 直贴前九条

唤出即粘

  • 全局快捷键默认 ⌘⇧V（Windows Ctrl+Shift+V），面板在鼠标附近弹出并抢到键盘； ⏎ 粘回原应用，⌥⏎ 只粘纯文本，双击行也行
  • 快捷键可改：设置窗里点一下、直接在键盘上按组合键，不用记 accelerator 语法
dedupe blake3("kind:content") 文本·富文本·图片·文件 命中只 use_count+1

采集与去重

  • 文本 / 富文本（HTML、RTF）/ 图片 / 文件都收，按 blake3 内容哈希去重并累计使用次数
  • 自己写回的粘贴被 guard 抑制，不会凭空多出一条
search FTS5 trigram 索引 "部署" → 降级 LIKE 短于 3 字符吃不下

搜索

  • SQLite FTS5 全文检索；两个汉字的短词自动降级 LIKE，否则命中不了
  • 类型与分组筛选、右侧即时预览、滚到底自动续页，几千条也不卡
tidy ⌘D 删 → 10 秒撤销 置顶 / 收藏 / 备注 / 分组 meta_at ≠ updated_at

整理

  • 置顶 / 收藏 / 备注 / 分组 / 敏感标记；⌘ 点多选批量删，删完 10 秒内可撤销
  • 这些改动不刷新排序时间（另记 meta_at），同步不会因为它们把整张列表重排一遍
sensitive bundle id / 进程名 密码管理器 → 不落库 不猜内容

敏感

  • 按前台应用身份过滤（macOS bundle id / Windows 进程名），不猜内容
  • 密码管理器里复制的东西默认不落库
sync argon2id + chacha20poly1305 采集后 1.2 秒推送 离线期间每轮留一包

同步

  • 自有 NAS 的 WebDAV + 端到端加密，NAS 上只有密文
  • 局域网与 Tailscale 双地址自动切换；对端离线期间每轮一包都留着（本机保留 7 天）， 回来一次补全，不丢中间几轮
backup CNST1 加密容器 口令 = 同步加密口令 清空前自动先导一份

备份

  • CNST1 加密容器导入导出，口令与同步加密口令同一把
  • 清空全部历史前自动先导一份
stack CGO_ENABLED=0 mygo 自绘 · 无 WebView 无 Node · 无 Electron

轻量

  • 纯 Go，CGO_ENABLED=0；界面用 mygo 自绘， 无 WebView、无 Node、无 Electron
  • 数据在 ~/Library/Application Support/clipnest（Windows %APPDATA%\clipnest）

快捷键

macOS 用 ⌘ · Windows 用 Ctrl；面板唤出时焦点本来就在搜索框里。

按键做什么
⌘⇧V唤出 / 收起面板（可在设置窗录成任意组合，含 F1–F12）
↑ ↓ ← →选择；PgUp / PgDn 翻页，Esc 收起（有勾选时先取消勾选）
⏎粘贴回原应用。中文输入法下要先提交候选再按一次（不输入时一次就粘）
⌘1-9直贴对应序号；带修饰键，不受输入法影响
⌥⏎只粘纯文本（富文本降级）
⌘F焦点回到搜索框（面板刚唤出时本来就在）
⌘D删当前条；有勾选时删勾选的那些（⌘ 点行 = 勾选）
⌘P / ⌘S / ⌘E置顶 / 收藏 / 敏感标记
⌘O / ⌘Y导出到文件（先问存哪）/ 复制回剪贴板

撤销删除与全选没有快捷键：⌘Z / ⌘A 在搜索框里会被输入框吃掉， 所以它们是筛选栏上两个看得见的按钮。

两端怎么连

NAS 上只存密文：内容在本地加密完才上传，服务端拿到的是不透明包。

设置 → 同步里各填一次。两个口令不是一回事，分别存进系统凭据：

填哪存成要求
WebDAV 账号口令系统凭据里
clipnest-webdav/本机名称		NAS 上那个账号的密码，各设备可以不同
加密口令系统凭据里
clipnest-sync/本机名称		端到端加密与备份共用；两台机器必须同一个字符串，否则拉下来解不开
/data/clipnest/ ├── mac-a-20261119T012345.678.json ← 每轮增量一包，名字带时刻，互不覆盖 ├── mac-b-20261119T013012.101.json ← Windows 同理，各写自己的包 ├── mac-a.json / mac-b.json ← 1.3.2 及更早的旧格式（还能读） └── blobs/ab/abcdef…png ← 图片原图，按内容哈希命名，两台共用一份

本机名称两台必须不同：文件名按它区分，填成一样会互相覆盖。 新设备第一次同步没有水位，会整段全量推一遍，能一次拿到对方全部历史；之后若对端漏了某一包， 用设置窗的「重新推送全部历史…」清水位重推（幂等，图片走台账不会重传）。 报错原文直接写在面板底栏与设置窗：PROPFIND: 401 是 WebDAV 口令不对， x509: certificate signed by unknown authority 是自签证书没勾。

常见问题

上面前四节基本都说到了；剩下这几条是最常被追问的。

回车没反应，只复制了？

粘贴是靠辅助功能合成 ⌘V 做的。没授权时面板顶部有条提示，点「去授权」直达系统设置。 macOS 上另有一种情形：从 ad-hoc 签名换到固定自签身份后旧授权会匹配不上， tccutil reset Accessibility com.clipnest.app 再勾一次就好。

数据放在哪，怎么彻底删掉？

macOS ~/Library/Application Support/clipnest，Windows %APPDATA%\clipnest： 里面是 clipnest.db（SQLite）、图片分片、自动轮转的日志。删掉这个目录、再到系统凭据里删掉那两条口令即可，不写别处。 清空历史可以只在应用内做（要输入确认词，且清空前自动先导一份加密备份）。

同步会不会把剪贴板传到别处？

不会。没有云端账号、没有遥测；目标就是你填的那个 WebDAV 目录，内容在本地加密后才上传，服务端只有密文。 口令存在系统钥匙串 / 凭据管理器里。

为什么不用 Electron / Tauri？

剪贴板监听、全局快捷键、文件进剪贴板、多屏挪窗这些框架层都现成；纯 Go 自绘让两端共用一套代码， 交叉编译不需要额外工具链，产物也没有 webview 运行时依赖。

能自己改吗？

能。MIT，go test ./... 193 项，提交前钩子跑 vet + test + Windows 交叉编译。 架构与 12 条行为契约在仓库的 docs/路线图.md。

In English

clipnest is a clipboard history manager for macOS and Windows written in pure Go: a menubar-resident panel opens with ⌘⇧V and pastes with ⏎. Text, rich text, images and files are collected and deduplicated by blake3 content hash; history lives in a local SQLite (FTS5) database; two machines sync through your own WebDAV NAS with end-to-end encryption (argon2id + chacha20poly1305), so the server only ever holds ciphertext. Sensitive apps are filtered by foreground app identity, not by guessing content. The UI is drawn by mygo, so there is no WebView, no Node and no cgo.
Install: brew tap nekoleamo/clipnest && brew install --cask clipnest (Windows: scoop install clipnest), or the one-line scripts in the install section. MIT licensed.

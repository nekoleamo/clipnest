# clipnest 路线图

> 最后更新：2026-11-15（P0、P1 完成）。本文是项目的总纲，具体执行细节见 `执行计划-下一步.md`。

## 一、产品定位（已定，不再讨论）

- **是什么**：跨平台（macOS + Windows）剪贴板历史管理器，菜单栏/托盘常驻，全局快捷键唤出面板，回车粘贴。
- **差异点**：剪贴板历史可通过**自有 NAS** 同步（WebDAV 或自写服务），不依赖第三方云。
- **不做**：WebView / Electron / Node 依赖；不做云端账号体系；不做移动端（至少 P0–P6 内不做）。

## 二、技术决策（已定案，改动需重开评估）

| 项 | 决策 | 依据 |
| --- | --- | --- |
| GUI 框架 | **Rust + nsh 0.5.1**（原生控件渲染） | P0 实测：Popup 面板、不抢焦点、键盘焦点、托盘、全局热键、更新器全部可用 |
| 语言 | **纯 Rust**（不用 TSX） | Rust 可直接操作平台 API，TSX 缺 SQLite/剪贴板监听/粘贴注入 |
| 壳 | **nsh 自己做壳**，不自建 AppKit 壳 | 延后 120ms 调 `focus()` 即解决键盘焦点问题，无需 objc2 壳 |
| 剪贴板 | `clipboard-rs 0.3` | 与 EcoPaste 同底层，跨平台（macOS `changeCount` 轮询 / Windows `WM_CLIPBOARDUPDATE`） |
| 存储 | SQLite + FTS5（`rusqlite` bundled） | 需全文搜索、去重、几万条量级；见 P1 |
| 同步 | 优先 **WebDAV**（NAS 自带），必要时自写服务 | NAS 零部署；协议简单、可移植 |
| 框架版本 | 锁 `nsh 0.5.1` | 0.x 阶段，升级需单独一轮复测（见 `2026-11-15-nsh-验证记录.md`） |

已知代价（接受）：
- 产物体积固定约 **50 MB**（`nsh-cli` 硬编码 runner features，无法裁剪），远大于 EcoPaste 的 10 MB
- nsh 0.x，API 可能 break；所有 nsh 调用集中在少数模块，便于升级

## 三、阶段规划

| 阶段 | 内容 | 验收 | 风险 |
| --- | --- | --- | --- |
| **P0** ✅ | 技术验证（窗口/焦点/快捷键/剪贴板/回环/粘贴/打包） | 已完成，见验证记录 | — |
| **P1** ✅ | 数据层：SQLite schema、FTS5、去重、分组、备份加密 | 已完成：`cargo test` 44 项全绿，见 `执行计划-下一步.md` 第七节 | 低 |
| **P2** ✅ | 采集与面板产品化：托盘、列表、搜索、粘贴动作、设置 | 已完成（Windows 冒烟待真机），见验证记录第九–十一节 | 中（UI 交互） |
| **P3** | 系统集成：权限引导、多显示器、拖拽导出、缩略图、敏感过滤 | 人工 | 中（进行中） |
| **P4** | 同步：WebDAV 增量同步 + 端到端加密 + 冲突策略 | 双机实测 | 中高（协议正确性） |
| **P5** | Windows 端：Win32 后端全部能力等价 | 真机/VM 实测 | 中（基础冒烟已过，剩能力等价） |
| **P6** | 发布：签名、公证、更新链、旧数据迁移 | 干净机器验证 | 中 |

依赖关系：P1 → P2 → P3；P4 可与 P3 并行；**P5 必须在 P2 之后尽早插队**（越晚发现 Windows 不可行，返工越贵）。

### 建议插入点

P2 的「面板能列出历史 + 回车粘贴」跑通后，**立刻做一次 Windows 冒烟**（只验证：窗口能开、PopKi 不抢焦、剪贴板能读写、Ctrl+V 能注入）。若 Windows 侧不成立，P4 的同步投入要重新评估（可能被迫改用其他壳）。

## 四、必须遵守的行为契约

以下 12 条来自 EcoPaste 的既有实现（`refactor/nsgo-migration` 分支 `docs/nsgo-migration/`），重写时不能走样：

1. `content_hash = blake3("<kind>:<content>")`
2. 文本的 HTML/RTF 条目必须同时具备 plain 文本才入库
3. 文件条目 `content` 为换行分隔的路径，`file_types` 为 `d`/`f` 串
4. 图片 `content` 为 PNG 文件名，资源存 `origin/` 与 `thumbnails/` 分片目录
5. 去重命中只 `use_count + 1` 并刷新 `updated_at`
6. 收藏/置顶/备注/分组的变更**不**刷新 `updated_at`
7. 搜索：长词走 FTS5，短词降级 LIKE
8. 置顶恒排最前
9. 收藏与置顶默认受清理保护
10. 自身写回必须被 guard 抑制，不产生新记录
11. `.ecopastebak` 加密容器字节布局不变（若要兼容导入）
12. 旧版数据导入只承诺历史记录，不扩大到设置迁移

## 五、里程碑与判定标准

| 里程碑 | 判定 |
| --- | --- |
| M1 可用（自己日常用） | macOS 上替换掉现有工具：托盘常驻、⌘⇧V 唤出、搜索、回车粘贴、历史持久化、开机自启 |
| M2 完整（功能对齐 EcoPaste） | 分组/收藏/备注/图片与文件条目/拖拽导出/敏感过滤/备份导入导出 |
| M3 多端 | Windows 能力对齐 + NAS 同步可用（两端互见、增量、不丢数据、不重复） |
| M4 可发布 | 签名公证、自动更新、干净机器首启、旧数据迁移路径 |

## 六、风险登记

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | **nsh Windows 后端运行时行为未验证** | 双端目标不成立 | 编译/打包已打通（macOS 交叉出 zip，见验证记录第九节），只剩运行时行为需真机；不行则评估 AppView 自建壳 / 换壳 |
| R1b | Windows 的 `AppOptions` 缺 `keep_alive_on_close` / `activation_policy` / `background` | 「关窗常驻 + 不抢焦点」形态不能照搬 macOS | 真机冒烟时专项测托盘与关窗行为 |
| R2 | nsh 0.x API 漂移 | 升级成本 | 锁 0.5.1；nsh 调用集中在 `src/platform.rs` 一层 |
| R3 | 面板焦点/时序回归 | 核心体验坏 | 每条平台行为改动后复跑 `tools/` 脚本（见验证记录第八节） |
| R4 | 同步写冲突/重复 | 数据脏 | 以 `content_hash` 为唯一键做 upsert；先上传后合并；删除用 tombstone |
| R5 | 体积 50 MB | 分发体验 | 接受；必要时压 dmg / 单架构出包 |
| R6 | 辅助功能权限被撤销 | 自动粘贴失效 | 启动与操作前检测 `AXIsProcessTrusted()`，跳转系统设置引导 |
| R7 | SQLite 放在网络盘 | 库损坏 | 库只在本地；NAS 上只存同步载荷（加密的 JSON/增量包） |

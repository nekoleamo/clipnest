# 发布与分发（P6 前置：零成本路线）

> 前提：**没有购买 Apple Developer Program**（$99/年），所以没有公证（notarization）。
> 结论与证据见 `docs/2026-11-15-nsh-验证记录.md` 第二十二节。
> 本文件只写「不花钱怎么让用户装上并跑起来」。

## 一、两条分发通道

| 通道 | 适合谁 | 首次拦截 |
| --- | --- | --- |
| **自建 Homebrew tap** | 愿意用 brew 的人 | 无（cask 的 `postflight` 删掉 quarantine） |
| **GitHub Releases（zip）** | 所有人 | 右键 → 打开；macOS 15+ 去「系统设置 → 隐私与安全性 → 仍要打开」 |

Windows 侧只有 SmartScreen「未知发布者」→「更多信息 → 仍要运行」，**不随更新重来**，不用额外处理。

## 二、打包

```bash
OWNER=<github 用户名> REPO=clipnest tools/release-go.sh 1.0.0
```

发版前先跑两个验证（可在干净机器上跑）：

```bash
tools/smoke-go.sh /Applications/clipnest.app/Contents/MacOS/clipnest   # 7 项端到端断言
tools/migrate-check.sh                                               # 旧库迁移：条目/FTS/图片/搜索/schema
```

脚本做这些事（`tools/release-go.sh`）：
1. `go test ./...` + `go vet ./...` + Windows/Linux 交叉编译
2. `go tool mygo build -platform darwin/universal,windows/amd64 -skip-installer`
   → `dist/darwin-universal/clipnest.app` + `clipnest-1.0.0.dmg`、`dist/windows-amd64/clipnest.exe`
3. `ditto` 成 `dist/clipnest-<ver>-macos.zip`（保留符号链接与扩展属性）、`zip` 成 `dist/clipnest-<ver>-windows-x86_64.zip`
4. 生成 `dist/SHA256SUMS`
5. 生成 `dist/clipnest.cask.rb`（填好 version + sha256）

`mygo build` 默认是 ad-hoc 签名。**本项目已改成固定自签身份**（`mygo.json` 的 `macos.signingIdentity: "clipnest-dev"`），
否则每次重打包 cdhash 会变，钥匙串口令的 ACL 与辅助功能（TCC）授权都会失效，得重新点一遍。

新机器上先建一次身份（详见 `tools/signing-identity.sh`）：

```bash
tools/signing-identity.sh            # 生成 clipnest-dev 自签证书 + 导入登录钥匙串 + 只信任代码签名
security find-identity -v -p codesigning | grep clipnest-dev
```

签好的要求是稳定的，可用这两条确认：

```bash
codesign -d -r- dist/darwin-arm64/clipnest.app   # => identifier "com.clipnest.app" and certificate root = H"…"
spctl -a -vvv dist/darwin-arm64/clipnest.app     # => accepted / origin=clipnest-dev
```

> 这只是本机自用。对外分发仍然需要 Developer ID + 公证（第七节），否则别人那里 Gatekeeper 会拦。

## 三、发版

```bash
gh release create v1.0.0 dist/clipnest-1.0.0-macos.zip dist/clipnest-1.0.0-windows-x86_64.zip \
   --title "clipnest 1.0.0" --notes-file docs/发布说明-1.0.0.md
```

然后把 `dist/clipnest.cask.rb` 复制到 tap 仓库：

```
<owner>/homebrew-clipnest/
└── Casks/clipnest.rb
```

用户侧：

```bash
brew tap <owner>/clipnest
brew install --cask clipnest
```

## 四、tap 里那个 cask 为什么能绕过 Gatekeeper

```ruby
postflight do
  system_command "/usr/bin/xattr",
                 args: ["-dr", "com.apple.quarantine", "#{appdir}/clipnest.app"]
end
```

下载来的 zip 带 `com.apple.quarantine` 属性，Gatekeeper 只对带这个属性的 app 做校验；
删掉它就等同于「用户自己构建的 app」。这也是为什么**官方 homebrew-cask 收不了**
（它要求已公证），但**自建 tap 没有这个审核**。

> ⚠️ 这只是分发便利，不是安全提升：用户跑的仍然是未签名的二进制。
> 所以 README 里要写清楚「本项目不签名不公证，自己判断是否信任」。

## 五、每次发版要动的东西

1. `mygo.json` 的 `version` 加一
2. 跑 `tools/release-go.sh`（会重新生成 cask 里的 sha256）
3. 建 Release、传两个 zip
4. 更新 tap 仓库里的 `Casks/clipnest.rb`
5. 若改了 `mygo.json` 的 `identifier`（现在是 `com.clipnest.app`），**同步调整 cask 的 `zap` 路径与登录项名字**

## 六、自动更新（还没接）

原理仍然成立：**浏览器下载才会打 `com.apple.quarantine`**，应用自己下载替换的文件没有这个标记，
所以「首次安装放行一次，后续更新不再拦截」。

迁移到 mygo 后更新器换成了框架自带的一套（`mygo keygen` 生成密钥、`mygo.json` 的 `updates` 段、
`mygo build -upload`），nsh 时代的 `latest.json` / `.sig` / `nsh update-manifest` 全部废弃，
`dist/` 里旧的 `latest.json*` 已删。

**现状：未启用。** 启用前要先拿到 GitHub token 与私钥（`MYGO_UPDATER_PRIVATE_KEY`），
并在一台机器上完整跑一次「旧版本 → 新版本」升级，验过才写进本文。启用前一律手动装包。

## 七、签名与公证（2026-11-17 决定不做）

> **决定：不做 Developer ID 签名与公证。** 自用 + 自建 tap 两个场景都不需要它：
> tap 里那条 cask 用 `postflight` 删 quarantine 已经能装能跑，本地开发用自签证书
> `clipnest-dev` 让钥匙串 ACL 与辅助功能授权在重打包后保持有效。
> 只有当「不认识的人从 Releases 下载」成为主要分发方式时，再回头看这一节。

以下作为备查留着（真付费才需要）：

- `codesign --options runtime --timestamp` + `notarytool submit --wait` + `xcrun stapler staple`
- 签名后 `spctl -a -vvv` 应输出 `source=Notarized Developer ID`
- 有了这道手续，官方 homebrew-cask 才能收，也不需要 cask 里删 quarantine 那段
- 顺带好处：Developer ID 签名稳定后，辅助功能的 TCC 授权不会再因为重新打包（ad-hoc 签名变化）而失效

脚本里已经把位置留出来：`tools/release-go.sh` 的 `go tool mygo build` 加 `-sign "Developer ID Application: …"`
（或 `mygo.json` 的 `macos.signingIdentity`），其余流程不变。

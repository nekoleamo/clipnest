# 发布与分发

> 前提：**不买 Apple Developer Program**（$99/年），因此没有公证（notarization）。
> 所以官方 homebrew-cask 收不了，也不能默认让「浏览器直下双击」顺畅——本文只写零成本、可用的那条路。

## 一、六个仓库

| 仓库 | 作用 |
| --- | --- |
| `nekoleamo/clipnest`（GitHub） | 主仓库 + Releases（产物与 `SHA256SUMS`） |
| `null_593_5354/clipnest`（Gitee） | 国内镜像：同一套产物，附件 URL 形状与 GitHub 一致 |
| `nekoleamo/homebrew-clipnest` | Homebrew tap：`Casks/clipnest.rb`（下载走 GitHub） |
| `null_593_5354/homebrew-clipnest`（Gitee） | tap 镜像：cask 里 URL 指向 **Gitee 附件** |
| `nekoleamo/scoop-clipnest` | Scoop bucket：`bucket/clipnest.json`（下载走 GitHub） |
| `null_593_5354/scoop-clipnest`（Gitee） | bucket 镜像：manifest 里 URL 指向 Gitee 附件 |

本机 remote：`origin` = GitHub，`gitee` = Gitee，两边都要推。

## 二、打包与发版（一次发版的完整命令）

```bash
# 1) 产物 + cask / scoop manifest / 安装脚本（版本号取自 mygo.json，可传参覆盖）
tools/release-go.sh 1.0.1

# 2) 安装脚本放回仓库根目录（一键安装的 raw URL 指这里，文件头注明是生成物）
cp dist/install.sh dist/install.ps1 . && chmod +x install.sh

# 3) 提交 + 打 tag + 双端推送
git add -A && git commit -m "chore: 发版 1.0.1"
git tag -a v1.0.1 -m "v1.0.1：…"
git push origin main && git push origin v1.0.1
git push gitee  main && git push gitee  v1.0.1

# 4) GitHub Release（gh 已登录）
cp dist/darwin-universal/clipnest-1.0.1.dmg dist/clipnest-1.0.1-universal.dmg
gh release create v1.0.1 --title v1.0.1 --notes-file NOTES.md \
  dist/clipnest-1.0.1-macos.zip dist/clipnest-1.0.1-windows-x86_64.zip \
  dist/clipnest-1.0.1-universal.dmg dist/SHA256SUMS dist/install.sh dist/install.ps1

# 5) tap 与 bucket（四个仓库各 commit 一次；Gitee 版用 .gitee. 那两份，URL 不同）
cp dist/clipnest.cask.rb          <gh-tap>/Casks/clipnest.rb
cp dist/clipnest.scoop.json       <gh-bucket>/bucket/clipnest.json
cp dist/clipnest.gitee.cask.rb    <gitee-tap>/Casks/clipnest.rb
cp dist/clipnest.gitee.scoop.json <gitee-bucket>/bucket/clipnest.json

# 6) Gitee 镜像：建 release + 传 4 个附件 + 匿名回查（凭据只从 env 来）
set -a; . ~/.pi/agent/local/secrets.env; set +a
GITEE_TOKEN="$GITEE_TOKEN" tools/gitee-release.sh v1.0.1
```

依赖有变化时先跑 `python3 tools/thirdparty.py`，把生成的 `THIRD-PARTY-LICENSES.md` 一起提交。

> ⚠️ **`SKIP_BUILD=1` 只适合「产物已编好、只重做归档/生成物」**：`ditto` 每次打出来的 zip 字节不同，
> 重打包会让已发布产物的 SHA256 对不上（cask/manifest 指向旧的、GitHub 上是旧包、Gitee 传成新包 →
> 三方哈希打架）。脚本现在在 `SKIP_BUILD=1` 且 zip 已存在时**直接复用**，不再重打。
> 真要换产物就整版重发，别原地替换。

## 三、发完自检

```bash
gh release view v1.0.1 --json assets --jq '.assets[].name'
shasum -a 256 dist/clipnest-1.0.1-macos.zip      # 与 cask 里的 sha256、与线上产物一致
curl -sI -L https://github.com/nekoleamo/clipnest/releases/download/v1.0.1/SHA256SUMS | head -1
CLIPNEST_NO_KILL=1 bash install.sh --dir /tmp/x --no-open   # 真产物走一遍一键安装
CLIPNEST_FROM=gitee CLIPNEST_NO_KILL=1 bash install.sh --dir /tmp/y --no-open  # 国内源
```

## 四、安装方式与国内双源

```bash
# macOS
brew tap nekoleamo/clipnest && brew trust --tap nekoleamo/clipnest && brew install --cask clipnest
curl -fsSL https://github.com/nekoleamo/clipnest/releases/latest/download/install.sh | sh

# Windows
scoop bucket add clipnest https://github.com/nekoleamo/scoop-clipnest && scoop install clipnest
irm https://github.com/nekoleamo/clipnest/releases/latest/download/install.ps1 | iex
```

国内把域名换成 Gitee（`gitee.com/null_593_5354/clipnest/raw/main/install.sh` 等）。

**为什么免签名也能装**：`brew` 用 curl、脚本用 curl / `Invoke-WebRequest`，下载的文件**不带**
`com.apple.quarantine` / Mark-of-the-Web，Gatekeeper 与 SmartScreen 都不介入。只有浏览器直接下 zip 才拦。

一键脚本做的事：选源（默认 `auto`：先 Gitee，不通换 GitHub；下载/校验失败还会自动换另一个源重试一次）
→ 取最新版本号 → 下载 zip 与 `SHA256SUMS` → **校验 SHA256，不符就中止** → 解包 → 装到
`/Applications`（不可写退 `~/Applications`）/ `%LOCALAPPDATA%\Programs\clipnest` → 清 quarantine（兜底）/
建开始菜单快捷方式。

> `auto` 先 Gitee 而不是 GitHub：GitHub 的发行版资产域（`release-assets.githubusercontent.com`）在国内
> 经常「API 探针通、真下载 SSL 断」，按探针选源会挑到它然后卡死十几秒后失败（2026-11-18 实测）。

管道执行时用环境变量：`CLIPNEST_FROM=github|gitee|auto`、`CLIPNEST_VERSION`、`CLIPNEST_DIR`、`CLIPNEST_REPO`。
自测：`bash tools/install_test.sh`（假发行版服务器，10 条断言）。

## 五、Homebrew 的两个新版门槛（2026-11 实测）

1. **第三方 tap 要显式信任**：否则 `Refusing to load cask … from untrusted tap`，先
   `brew trust --tap <user>/<repo>`（信任记录在 `~/.homebrew/trust.json`，每个 tap 一次）。
2. **`postflight` 已废弃**，要用 `postflight_steps`；且 steps DSL 里**没有 `appdir` 方法**，
   路径必须用模板 token：

   ```ruby
   postflight_steps do
     run "/usr/bin/xattr", args: ["-dr", "com.apple.quarantine", "{{appdir}}/clipnest.app"]
   end
   ```

   写成 `"#{appdir}/…"` 会加载失败；写相对路径 + `base: :appdir` 只作用于命令、不作用于参数。

## 六、Scoop bucket

bucket 就是一个放 manifest 的 git 仓库，免费、无审核、不要求签名（`Invoke-WebRequest` 下载同样不带隔离标记）。

1. 发版时拿到 `dist/clipnest.scoop.json`
2. 建仓库 `<owner>/scoop-clipnest`，把文件放成 `bucket/clipnest.json`
3. 用户：`scoop bucket add clipnest <仓库 URL>` → `scoop install clipnest`

manifest 里带 `checkver`（读 GitHub releases）与 `autoupdate`；维护时在 bucket 仓库跑
`scoop checkver clipnest -u` 追版本（hash 另按提示重算）。

## 七、更新提示（只查不装）

设置窗「版本与更新」先选**更新源**（GitHub / Gitee / 自定义），再填 `owner/repo`，点「检查更新」拉
`<源>/repos/<repo>/releases/latest`，与 `mygo.App.Version()` 比版本号，有新版本给提示并可「打开发布页」；
托盘菜单也有入口。

- **Gitee**：API 根是 `https://gitee.com/api/v5`（比 GitHub 多一层 `/api/v5`），响应里没有 `html_url`，
  发布页链接用 `tag_name` 拼 `https://gitee.com/<repo>/releases/tag/<tag>`；发布时间字段是 `created_at` 而非 `published_at`。
- **自定义**：填 API 根（如反代 `https://<host>/api.github.com`），「打开发布页」优先用响应里的 `html_url`，
  没有就按 API 根的 scheme+host 拼。
- 切换源时若仓库名还是空/上一个源的默认值，会自动带出该源上的本仓镜像（`nekoleamo/clipnest` ↔ `null_593_5354/clipnest`）。
  国内默认该用 Gitee：`api.github.com` 直连不稳，超时是 8 秒。

**刻意不做自动下载替换**：签名已决定不做，自动替换未签名二进制等于绕过用户对 Gatekeeper 的确认。
哪天做了 Developer ID 签名，再考虑接框架自带的上传/下载链路。

## 八、签名与公证（决定不做）

自用 + 自建 tap 两个场景都不需要：tap 里那条 cask 用 `postflight_steps` 删 quarantine 即可；
本地开发用自签证书 `clipnest-dev`，让钥匙串 ACL 与辅助功能授权在重打包后保持有效。

只有「陌生人不通过包管理器、直接从浏览器下载」成为主要分发方式时，再回头看这一节
（`codesign --options runtime --timestamp` + `notarytool submit --wait` + `xcrun stapler staple`，
脚本里 `tools/release-go.sh` 已给 `-sign` 留了位置）。

## 九、Gitee 建 release 的坑（两个，都踩过）

1. **接口只吃 formData**：`POST /repos/{owner}/{repo}/releases` 的参数全是 formData，
   且 `target_commitish` 必填。发 `application/json` body 会被当成「没带参数」回 **404**，
   看起来跟权限问题一模一样。`tools/gitee-release.sh` 已经用 `-F` 发表单。
2. **仓库要纳入 token 的授权仓库列表**：Gitee 对「已登录但没纳管该仓库」也回 **404**（不是 403）。

脚本自测：`bash tools/gitee-release_test.sh`（假 Gitee API，8 条断言）。换产物时用
`GITEE_REPLACE=1`（同名附件先删再传，否则会跳过、留下旧文件）。

# 发布

## 零、四个仓库

| 仓库 | 作用 |
| --- | --- |
| `nekoleamo/clipnest`（GitHub） | 主仓库 + Releases（产物与 `SHA256SUMS`） |
| `null_593_5354/clipnest`（Gitee） | 国内镜像：同一套产物，`releases/download/<tag>/<file>` 形状与 GitHub 一致 |
| `nekoleamo/homebrew-clipnest`（GitHub） | Homebrew tap：`Casks/clipnest.rb`（下载走 GitHub） |
| `nekoleamo/scoop-clipnest`（GitHub） | Scoop bucket：`bucket/clipnest.json`（下载走 GitHub） |
| `null_593_5354/homebrew-clipnest`（Gitee） | tap 的国内镜像：cask 的 URL 指向 **Gitee 附件**，拉包也走 Gitee |
| `null_593_5354/scoop-clipnest`（Gitee） | bucket 的国内镜像：manifest 的 URL 指向 Gitee 附件 |

> 两份 cask / manifest 由 `tools/release-go.sh` 一次生成：`dist/clipnest.cask.rb` +
> `dist/clipnest.scoop.json`（GitHub 版）与 `dist/clipnest.gitee.cask.rb` +
> `dist/clipnest.gitee.scoop.json`（Gitee 版），只有 URL 的域名不同。

本机 remote：`origin` = GitHub 主仓库，`gitee` = Gitee 镜像（推完记得两边都推）。

## 零点半、为什么这条路零成本

> 这一节是 P6 的前置结论：不花钱怎么让用户装上并跑起来。

> 前提：**没有购买 Apple Developer Program**（$99/年），所以没有公证（notarization）。
> 结论与证据见 `docs/2026-11-15-nsh-验证记录.md` 第二十二节。
> 本文件只写「不花钱怎么让用户装上并跑起来」。

## 一、两条分发通道

| 通道 | 适合谁 | 首次拦截 |
| --- | --- | --- |
| **自建 Homebrew tap** | 愿意用 brew 的人 | 无：`brew` 用 curl 下载不带 quarantine；cask 里 `postflight_steps` 再兜底删一次 |
| **GitHub Releases（zip）** | 所有人 | 右键 → 打开；macOS 15+ 去「系统设置 → 隐私与安全性 → 仍要打开」 |

Windows 侧只有 SmartScreen「未知发布者」→「更多信息 → 仍要运行」，**不随更新重来**，不用额外处理。

## 二、打包

```bash
tools/release-go.sh 1.0.0            # 默认 OWNER=nekoleamo，GITEE_OWNER=null_593_5354
```

发版前先跑两个验证（可在干净机器上跑）：

```bash
tools/smoke-go.sh /Applications/clipnest.app/Contents/MacOS/clipnest   # 7 项端到端断言
tools/migrate-check.sh                                               # 旧库迁移：条目/FTS/图片/搜索/schema
```

脚本做这些事（`tools/release-go.sh`）：
1. `go test ./...` + `go vet ./...` + Windows/Linux 交叉编译
2. `go tool mygo build -platform darwin/universal,windows/amd64 -skip-installer`
   → `dist/darwin-universal/clipnest.app` + `clipnest-1.0.0.dmg`、`dist/windows-amd64/clipnest.exe`
3. `ditto` 成 `dist/clipnest-<ver>-macos.zip`（保留符号链接与扩展属性）、`zip` 成 `dist/clipnest-<ver>-windows-x86_64.zip`
4. 生成 `dist/SHA256SUMS`
5. 生成 `dist/clipnest.cask.rb`（填好 version + sha256）

`mygo build` 默认是 ad-hoc 签名。**本项目已改成固定自签身份**（`mygo.json` 的 `macos.signingIdentity: "clipnest-dev"`），
否则每次重打包 cdhash 会变，钥匙串口令的 ACL 与辅助功能（TCC）授权都会失效，得重新点一遍。

新机器上先建一次身份（详见 `tools/signing-identity.sh`）：

```bash
tools/signing-identity.sh            # 生成 clipnest-dev 自签证书 + 导入登录钥匙串 + 只信任代码签名
security find-identity -v -p codesigning | grep clipnest-dev
```

签好的要求是稳定的，可用这两条确认：

```bash
codesign -d -r- dist/darwin-arm64/clipnest.app   # => identifier "com.clipnest.app" and certificate root = H"…"
spctl -a -vvv dist/darwin-arm64/clipnest.app     # => accepted / origin=clipnest-dev
```

> 这只是本机自用。对外分发仍然需要 Developer ID + 公证（第七节），否则别人那里 Gatekeeper 会拦。

## 三、发版

```bash
gh release create v1.0.0 dist/clipnest-1.0.0-macos.zip dist/clipnest-1.0.0-windows-x86_64.zip \
   --title "clipnest 1.0.0" --notes-file docs/发布说明-1.0.0.md
```

然后把 `dist/clipnest.cask.rb` 复制到 tap 仓库：

```
<owner>/homebrew-clipnest/
└── Casks/clipnest.rb
```

用户侧：

```bash
brew tap <owner>/clipnest
brew install --cask clipnest
```

## 三点五、一次发版的完整命令（2026-11-17 v1.0.0 实测走过）

```bash
# 1) 产物 + cask + scoop manifest + 安装脚本
tools/release-go.sh 1.0.0
cp dist/install.sh dist/install.ps1 .          # 一键安装的 raw URL 指根目录这两份
git add -A && git commit -m "chore: 发版 1.0.0"

# 2) 打 tag 并推到两边
git tag -a v1.0.0 -m "v1.0.0：…"
git push origin main && git push origin v1.0.0
git push gitee  main && git push gitee  v1.0.0

# 3) GitHub Release（gh 已登录）
cp dist/darwin-universal/clipnest-1.0.0.dmg dist/clipnest-1.0.0-universal.dmg
gh release create v1.0.0 --title v1.0.0 --notes-file NOTES.md \
  dist/clipnest-1.0.0-macos.zip dist/clipnest-1.0.0-windows-x86_64.zip \
  dist/clipnest-1.0.0-universal.dmg dist/SHA256SUMS dist/install.sh dist/install.ps1

# 4) tap 与 bucket（四个仓库各 commit 一次：GitHub 版 + Gitee 版）
cp dist/clipnest.cask.rb        <gh-tap>/Casks/clipnest.rb
cp dist/clipnest.scoop.json     <gh-bucket>/bucket/clipnest.json
cp dist/clipnest.gitee.cask.rb  <gitee-tap>/Casks/clipnest.rb
cp dist/clipnest.gitee.scoop.json <gitee-bucket>/bucket/clipnest.json

# 5) Gitee 镜像（凭据只从 env 来，脚本不读 secrets 文件）
set -a; . ~/.pi/agent/local/secrets.env; set +a
GITEE_TOKEN="$GITEE_TOKEN" tools/gitee-release.sh v1.0.0
```

> ⚠️ **Gitee 建 release 返回 404 的两种真因**（都踩过）：
> 1. **请求体格式**：这个接口按 swagger 只吃 **formData**（multipart/表单），并且 `target_commitish` **必填**。
>    发 `application/json` body 会被当成「没带参数」，回 404——看起来跟权限问题一模一样。
>    脚本现在用 `-F` 发表单、`target_commitish` 取 `git rev-parse <tag>^{commit}`。
> 2. **仓库没纳入 token 的授权仓库列表**：Gitee 对「已登录但没纳管该仓库」也回 404（不是 403）。
>    处理：Gitee → 设置 → 私人令牌，把新仓库加进去；或用带 `projects` 写权限的令牌。
> 脚本现在会先 `GET /user` 打出 token 属于谁、再读一次仓库，404 时把这两条信息一起抛出来。
> 自测：`bash tools/gitee-release_test.sh`（假 Gitee API，7 条断言）。

发完自检（都做过了，留着下次照抄）：

```bash
gh release view v1.0.0 --json assets --jq '.assets[].name'
shasum -a 256 dist/clipnest-1.0.0-macos.zip     # 与 cask 里的 sha256 一致
CLIPNEST_NO_KILL=1 bash install.sh --dir /tmp/x --no-open   # 真发版产物走一遍一键安装
```

## 三点七、Homebrew 的两个新版门槛（2026-11 实测）

1. **第三方 tap 要显式信任**：新版 Homebrew 对非官方 tap 里的 cask 直接拒绝加载
   （`Refusing to load cask … from untrusted tap`），用户得先 `brew trust --tap <user>/<repo>`
   （或 `brew trust --cask`）。README 与两个 tap 的安装命令都写了两步。
2. **`postflight` 已废弃**：警告要求改 `postflight_steps`。而且 steps DSL 里**没有 `appdir` 方法**，
   路径要用模板 token：`run "/usr/bin/xattr", args: ["-dr", "com.apple.quarantine", "{{appdir}}/clipnest.app"]`。
   写成 `"#{appdir}/…"` 会加载失败（`undefined local variable or method 'appdir'`），写成相对路径
   `"clipnest.app" + base: :appdir` 则只作用于命令本身、不作用于参数——这两种都试过了。

## 四、tap 里那个 cask 为什么能绕过 Gatekeeper

```ruby
postflight do
  system_command "/usr/bin/xattr",
                 args: ["-dr", "com.apple.quarantine", "#{appdir}/clipnest.app"]
end
```

下载来的 zip 带 `com.apple.quarantine` 属性，Gatekeeper 只对带这个属性的 app 做校验；
删掉它就等同于「用户自己构建的 app」。这也是为什么**官方 homebrew-cask 收不了**
（它要求已公证），但**自建 tap 没有这个审核**。

> ⚠️ 这只是分发便利，不是安全提升：用户跑的仍然是未签名的二进制。
> 所以 README 里要写清楚「本项目不签名不公证，自己判断是否信任」。

## 五、每次发版要动的东西

0. `tools/release-go.sh <版本>` 会在 `dist/` 生成 cask / scoop manifest / 拷好仓库名的
   `install.sh`、`install.ps1`；**把这两个安装脚本复制到仓库根目录并提交**（一键安装的 raw URL 指的就是根目录那份）
0. `python3 tools/thirdparty.py`（依赖有变化时；生成的 `THIRD-PARTY-LICENSES.md` 要一起提交）
1. `mygo.json` 的 `version` 加一
2. 跑 `tools/release-go.sh`（会重新生成 cask 里的 sha256）
3. 建 Release、传两个 zip
4. 更新 tap 仓库里的 `Casks/clipnest.rb`
5. 若改了 `mygo.json` 的 `identifier`（现在是 `com.clipnest.app`），**同步调整 cask 的 `zap` 路径与登录项名字**

## 五点五、一键安装脚本（curl / iwr）与国内双源

两条命令就装完，不经过包管理器，**也不需要签名/公证**——`curl` 与 `Invoke-WebRequest`
下载的文件不带 `com.apple.quarantine` / Mark-of-the-Web，所以 Gatekeeper 和 SmartScreen
都不会拦（比浏览器点下载更干净）。

```bash
# macOS（GitHub）
curl -fsSL https://raw.githubusercontent.com/<owner>/clipnest/main/install.sh | sh
# macOS（国内走 Gitee）
curl -fsSL https://gitee.com/<owner>/clipnest/raw/main/install.sh | sh
```

```powershell
# Windows（GitHub）
irm https://raw.githubusercontent.com/<owner>/clipnest/main/install.ps1 | iex
# Windows（国内走 Gitee）
irm https://gitee.com/<owner>/clipnest/raw/main/install.ps1 | iex
```

脚本行为：选下载源 → 取最新版本号 → 下载 zip 与 `SHA256SUMS` → **校验 SHA256**（不符就中止，
什么都不装）→ 解开 → 装到 `/Applications`（不可写则 `~/Applications`）/ `%LOCALAPPDATA%\Programs\clipnest`
→ 清 quarantine（兜底）/ 建开始菜单快捷方式。

可选控制（管道执行时用环境变量）：

| 变量 | 作用 |
| --- | --- |
| `CLIPNEST_FROM=github\|gitee\|auto` | 下载源，默认 `auto`：先试 GitHub，3 秒不通换 Gitee |
| `CLIPNEST_VERSION=v1.2.3` | 装指定版本 |
| `CLIPNEST_DIR=/path` | 装到哪 |
| `CLIPNEST_REPO=owner/repo` | 仓库（`install.sh` 里的占位符没被发布脚本填过时才需要） |

`tools/install_test.sh` 是本机可跑的端到端测试：起一个假「发行版服务器」，覆盖正常安装、
哈希不符必须中止、`auto` 在 GitHub 不通时切 Gitee、`--from gitee` 直连四种情况（7 条断言）。

### 国内双源：GitHub + Gitee 镜像

两边的发行版结构完全一样，脚本只换域名：

| | GitHub | Gitee |
| --- | --- | --- |
| 发行版 API | `https://api.github.com/repos/<o>/<r>/releases/latest` | `https://gitee.com/api/v5/repos/<o>/<r>/releases/latest` |
| 附件地址 | `https://github.com/<o>/<r>/releases/download/<tag>/<file>` | `https://gitee.com/<o>/<r>/releases/download/<tag>/<file>` |
| 单文件上限 | 2 GB | **100 MB**（GVP 200 MB） |
| 匿名下载 | ✅ | ✅（302 跟随即可） |

我们的产物是 16 MB（.app zip）和 18 MB（exe zip），离上限很远。
Gitee 侧上传走 API：`POST /api/v5/repos/<o>/<r>/releases/<id>/attach_files`（multipart，带 access_token），
或者直接在网页上「发行版 → 上传附件」。

> tap 仓库与 scoop bucket 也可以镜像到 Gitee：`brew tap <o>/clipnest https://gitee.com/<o>/homebrew-clipnest`
> 和 `scoop bucket add clipnest https://gitee.com/<o>/scoop-clipnest` 都能用，git 协议不挑域名。

## 五点七、Windows：Scoop 自建 bucket

Scoop 的 bucket 就是一个放 manifest 的 git 仓库，免费、无审核、不要求签名；它下载同样不带
Mark-of-the-Web，所以不会弹 SmartScreen「未知发布者」。

1. 发版时 `tools/release-go.sh` 会生成 `dist/clipnest.scoop.json`
2. 建仓库 `<owner>/scoop-clipnest`，把那个文件复制成 `bucket/clipnest.json`
3. 用户侧：

```powershell
scoop bucket add clipnest https://github.com/<owner>/scoop-clipnest
scoop install clipnest        # 升级 scoop update clipnest
```

manifest 里带了 `checkver`（读 GitHub releases）与 `autoupdate`；维护时在 bucket 仓库里跑
`scoop checkver clipnest -u` 会自动更新版本号与 URL（hash 用 `scoop checkver clipnest -u` 之后
按提示重算，或手工跑一次 `sha256sum`）。

## 六点五、更新提示（2026-11-17 已接，只查不装）

设置窗「版本与更新」里填更新源（`owner/repo`）+ 点「检查更新」：拉
`https://api.github.com/repos/<repo>/releases/latest`，和 `mygo.App.Version()` 比版本号，
有新版本就给提示并提供「打开发布页」；托盘菜单也有「检查更新」入口。

**刻意不做自动下载替换**：签名/公证已决定不做，自动替换一个未签名二进制等于绕过用户对
Gatekeeper 的确认。等哪天做了 Developer ID 签名，再考虑接框架自带的上传/下载链路。

`internal/update` 只做三件事：请求最新发布（8 秒超时、响应上限 256 KiB）、版本号比较
（`v1.2.3` 这种点分数字，解析不了退回字符串比较）、发布说明截断。测试用 httptest
覆盖正常/404/403/坏 JSON/超时五种情况。

## 六、自动更新（框架那套，未启用）

原理仍然成立：**浏览器下载才会打 `com.apple.quarantine`**，应用自己下载替换的文件没有这个标记，
所以「首次安装放行一次，后续更新不再拦截」。

迁移到 mygo 后更新器换成了框架自带的一套（`mygo keygen` 生成密钥、`mygo.json` 的 `updates` 段、
`mygo build -upload`），nsh 时代的 `latest.json` / `.sig` / `nsh update-manifest` 全部废弃，
`dist/` 里旧的 `latest.json*` 已删。

**现状：未启用。** 启用前要先拿到 GitHub token 与私钥（`MYGO_UPDATER_PRIVATE_KEY`），
并在一台机器上完整跑一次「旧版本 → 新版本」升级，验过才写进本文。启用前一律手动装包。

## 七、签名与公证（2026-11-17 决定不做）

> **决定：不做 Developer ID 签名与公证。** 自用 + 自建 tap 两个场景都不需要它：
> tap 里那条 cask 用 `postflight` 删 quarantine 已经能装能跑，本地开发用自签证书
> `clipnest-dev` 让钥匙串 ACL 与辅助功能授权在重打包后保持有效。
> 只有当「不认识的人从 Releases 下载」成为主要分发方式时，再回头看这一节。

以下作为备查留着（真付费才需要）：

- `codesign --options runtime --timestamp` + `notarytool submit --wait` + `xcrun stapler staple`
- 签名后 `spctl -a -vvv` 应输出 `source=Notarized Developer ID`
- 有了这道手续，官方 homebrew-cask 才能收，也不需要 cask 里删 quarantine 那段
- 顺带好处：Developer ID 签名稳定后，辅助功能的 TCC 授权不会再因为重新打包（ad-hoc 签名变化）而失效

脚本里已经把位置留出来：`tools/release-go.sh` 的 `go tool mygo build` 加 `-sign "Developer ID Application: …"`
（或 `mygo.json` 的 `macos.signingIdentity`），其余流程不变。

# 变更记录

## 1.3.5（2026-11-19）

- **修（「重新推送全部历史」的提示不消失）**：那句话写在设置窗自己的 status 里，没人会去清，
  于是一直挂着「已安排重新推送全部历史（同步中…）」，看着像永远在同步。现在点完只把同步状态改成
  「🔄 正在同步中…（重新推送全部历史）」，跑完由结果覆盖；`runSync` 也不再重复写一次「正在同步中」
  把这条补充说明盖掉
- 测试：193 项全绿（新增「点完不留残留提示、跑完不显示正在同步中」）

## 1.3.4（2026-11-19）

- **新（设置窗「重新推送全部历史…」）**：清掉 `sync_last_export` 水位，下一轮把整段历史重推一遍。
  以前水位只会往前走，对端在某一包上漏了（旧版本覆盖写、包过期被删、本机换过库）就永远补不回来。
  一台设备**第一次**同步本来就是全量（没有水位），这个入口是给「已经同步过、但缺东西」的情形
- **修（图片原图每次都被重传）**：图片条目每改一次备注/置顶都会重新进增量，而 `pushBlobs` 无条件
  重传整张原图。新增迁移 v4 的 `synced_blobs` 台账，推过的（以及从对端拉来的）都记上，之后不再传
- 测试：192 项全绿（新增「重推会重新导出全量」「图片只推一次」两项）

## 1.3.3（2026-11-19）

- **改（增量包改成「一包一个文件」）**：远端不再是每设备一个会被覆盖的 `<本机名称>.json`，而是
  `<本机名称>-<时刻>.json`，每轮有变更就新写一包。以前对端离线期间推的第二轮会把第一轮覆盖掉，
  回来的那台只拿到最后一包、中间条目静默丢失；现在全部保留，回来一次补全
- 已合并的包按包名里的时刻记水位（`meta.sync_seen_<设备>`），不再每轮重复下载
- 自己的包保留 7 天（`sync.PackageKeepDays`）后由本机删除，**别人的包一律不碰**
- 同一毫秒连推两轮时把时刻往后挪一格，避免同名覆盖
- 旧格式 `<本机名称>.json` 仍会被读取合并（不删、不清），两台都升级后可手删
- 跳过包的日志按「包 + 原因」节流到 10 分钟一条：对端口令不对时那一包每 5 秒重试一次，
  以前会把 2MB 的日志刷满、轮转掉有用记录
- 测试：190 项全绿（新增包名往返/设备名带 `-`、离线补全、水位跳过、只删自己的旧包）

## 1.3.2（2026-11-19）

- **修（点「立即同步」还挂着上一轮的报错）**：以前状态是异步 worker 里才改的，点完那一刻界面上
  仍是上次的 `❌ …`，看着像又失败了一次。现在 `StartSync` 先**同步**把状态换成「🔄 正在同步中…」
  并清掉上一轮结果，跑完再替换成最终结果
- **修（后台写的状态在设置窗里不刷新）**：`invalidate()` 只重画面板，设置窗里的同步结果、看门狗
  告警要等用户动一下鼠标才更新。现在面板、设置窗、预览窗一起重画
- 状态行按内容上色：❌ 红 / ⚠️ 黄 / ✅ 绿 / 进行中灰
- 测试：186 项全绿（新增「进行中 → 结果」那一档，假同步卡在 channel 上断言两个阶段）

## 1.3.1（2026-11-19）

- **改（口令拆成两个框）**：`WebDAV 账号口令` 与 `加密口令（端到端加密 + 备份）` 分开填，
  分别写 `clipnest-webdav/<本机名称>` 与 `clipnest-sync/<本机名称>`。以前只有一个框、
  同时写两处，NAS 密码和加密口令必须填成同一个才行
- **改（清空前的备份口令）**：只认加密口令（设置窗里填的，或系统凭据里存着的那个），
  不再拿 WebDAV 账号口令兜底 —— 拿 NAS 密码加密出来的备份以后没人记得住
- **修（测试会写真钥匙串）**：macOS 那份凭据实现直接调 Security 框架、不看有没有事件循环，
  所以 `SavePrefs` 的测试会**真的往登录钥匙串里写条目**（实测留下一条
  `clipnest-sync/<主机名>-local`，已清）。`secretGet` / `secretSet` 现在都可注入，测试全部替换
- 文档：README 新增「两端同步怎么填」（两个口令的条目名、必须一致的那一个、自签证书、
  凭据管理器 GUI 不能改、三条常见报错各是什么）
- 测试：185 项全绿（新增「两个口令分别落进两条凭据」一项）

## 1.3.0（2026-11-19）

设置窗从「基本点不动」修成可用，快捷键改成按组合键录制，清空历史加了备份兜底。
下面第一条是 1.0.0 起就有的老毛病，只是之前没人真去点设置窗。

- **修（设置窗全表单失效）**：控件的绑定值以前是视图函数里的局部变量，每帧重建时又被
  `settings.json` 的旧值盖回去。表现：历史条数 `+` 只能跳到 5100、`−` 卡在 4900（面板高度、
  历史清理天数同病）、复选框点了不回勾、输入框打不进字、两个选项卡选不中、
  更新源下拉切不了。现在整张表改成跨帧草稿 `prefsForm`，点「保存」才落盘，
  重开设置窗走 `ResetPrefsForm()` 重新读盘
- **修（设置窗里的按钮是死的）**：`a.later()` 排的动作只有面板视图帧末的 `runPending()` 会跑，
  设置窗与预览窗都没调过——「保存更新源」「检查更新」「打开发布页」以及预览窗「点任意处关闭」
  全都点了没反应。两个视图的帧末各补一次 `a.runPending()`
- **修（菜单栏多一个图标）**：`TrayOptions.Title: "❐"` 在 macOS 是画在图标旁边的文字，
  视觉上就是一个重复图标；去掉 `Title`，改用 `ToolTip`
- **修（口令输入框藏错了地方）**：它原来嵌在「WebDAV」分支里，选**本地目录**时既设不了端到端
  加密口令，也导不了 / 导不进备份（只会提示「请先填口令」）。现在两种模式都在
- **修（面板高度立刻生效）**：设置里的面板高度以前只在启动建窗时读一次，改完得重启；
  现在保存时直接 `SetSize`。下限从 240 对齐到窗口的 300（设得比窗口下限还小等于白点）
- **修（日志每行写两遍）**：`app.logf` 同时转给 `store.Logf` 和 `settings.Logf`，而两者都指向
  同一个 `log.Printf`，所以 `clipnest.log` 里 CAPTURE / SYNC 那些行都是双份。现在只转一个出口
- 设置窗的滚动区改成 `KeepScrollbars(true)`：内容有 ≈1350pt，没滚动条时用户以为只有首屏那几节
- **新（快捷键改成「按组合键」录制）**：原来是让人往输入框里手打 `CmdOrCtrl+Shift+V` 这种
  accelerator 语法，既容易打错也没人记得语法。现在点一下那个框进入录制态，直接在键盘上按
  `⌘⇧K` 就成了（`Esc` 或点到别处取消）。录制期间先把旧快捷键摘掉，否则按到它时面板会被
  唤出、录制框收不到键；录完/取消/关窗都会挂回去。跨平台仍按系统显示（`⌘⇧K` / `Ctrl+Shift+K`）
- **修（改元数据有时同步不出去）**：时间戳只到毫秒，同一毫秒里「插入」再「置顶/收藏/备注」时
  `meta_at` 和 `updated_at` 打平，对端 merge 按「谁更新」比较会当成本地不旧 → 这次改动永远出不了
  本机。`UpdateMeta` 现在保证 `meta_at` 严格前进（`model.After`），也修掉了
  `TestMetaChangeReachesOtherDevice` 十次挂四五次的抖动
- **改（清空全部历史更难误触）**：点「清空全部历史…」后不再是一个「再点一次确认」的按钮，
  改为要输入「清空」解锁，**而且清空前自动导一份加密 .cnbak 到 `<数据目录>/backups/`**；
  没填口令就既不备份也不清空（清空不可撤销，墓碑还会随同步推到别的设备）
- **修（设置保存没加锁 / 采集读设置没加锁）**：`SavePrefs` 写 `a.Settings` 没进 `a.mu`
  （其它写入点都进了），而采集回调可能在别的 goroutine 上读它；现在写走锁，采集侧读
  `settingsSnapshot()` 副本
- **改（清空前的备份口令不必手填）**：设置窗里没填就用系统凭据里存着的那个同步口令
  （只在点「确认清空」那一下读），两者都没有才拒绝清空
- **改（安装脚本提示文案）**：`· 菜单栏出现 ❐ 图标` 改成「剪贴板图标」——`❐` 是以前托盘 Title
  的文字，1.3.0 已经去掉了
- 测试：新增 `internal/app/prefs_test.go` 16 项 + `db` 时间戳推进 1 项，按症状逐条钉住
  （数字增减、选项卡、复选框、打字、保存落盘、本地模式口令、更新源切换、重开丢弃未保存编辑、
  快捷键录制/取消/必须带修饰键/点别处取消、清空先备份 + 解锁词 + 用存着的口令）；
  `go test ./...` 184 项，连跑 3 遍全绿

## 1.2.0（2026-11-18）

分发与「检查更新」链路去掉了对 GitHub 的硬依赖，国内网络的下载与查版本都不再卡。

- 新：设置窗「版本与更新」的**更新源可配**（Gitee / GitHub / 自动 / 自定义 API 根），默认 **Gitee**；
  `auto` 先查 Gitee、5 秒不通自动换 GitHub，换源时仓库名也跟着换成该源上的镜像名；仓库留空即用内置镜像仓库
- 新：`internal/update` 支持 Gitee 的形状差异（API 根多一层 `/api/v5`、无 `html_url` 用 `tag_name` 拼发布页、
  发布时间字段是 `created_at`）
- 修：一键安装脚本 `auto` 改为**先 Gitee**，并在下载/校验失败时**自动换另一个源重试**——之前按 3 秒 API 探针
  选中 GitHub，而真实资产域 `release-assets.githubusercontent.com` 在国内常是「探针通、下载 SSL 断」，
  实测卡 11 秒后报错、什么都没装
- 修：`install.ps1` 同样改为 Gitee 优先
- 测试：`tools/install_test.sh` 增到 10 条断言（含「首选源资产坏掉 → 换源装上」）；`go test ./...` 166 项
- 文档：README / `docs/发布.md` 写清各源与自动切换规则；`uishot` 加 `-src` 便于渲染不同源的设置窗版式

## 1.1.0（2026-11-18）

依赖升级 + 一处数据安全修复，功能与 1.0.1 一致。

- **升级**：`mygo` 0.9.1 → **0.10.0**（API 与行为无破坏，`go test ./...`、交叉编译、headless 渲染均复验），
  以及 `klauspost/cpuid`、`golang.org/x/net`、`modernc.org/libc`、`modernc.org/memory`
- **修（数据安全）**：连删两批条目时，第一批的 10 秒清理定时器会把**第二批还在撤销窗口内的图片文件**
  删掉，导致「撤销」恢复出一个原图缺失的条目；现在每批只清理自己那批的文件，上一批被替换时立即回收
- 清理：`staticcheck` 全绿（删掉 `rowMenuBuilds`、`fitSize`、`cgHandle`、测试里没用的 helper）
- 修：WebDAV 口令写入系统凭据失败时不再静默，会在设置窗报出来
- 文档：mygo 版本号同步到各处；`docs/变更记录.md` 补 1.0.1 / 1.1.0

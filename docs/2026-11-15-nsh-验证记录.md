# nsh 可行性验证记录（2026-11-15，macOS）

验证工程即本仓库 `src/`（v0 骨架）。环境：macOS，Rust 1.100.0（Homebrew），nsh 0.5.1。

## 结论

macOS 侧技术路线成立，**不需要自建 AppKit 壳**。nsh 的 `WindowKind::Popup` 足够做剪贴板面板，唯一的缺口（收不到键盘）靠「延后一次 `focus()`」修掉。

## 一、打包与构建

| 项 | 实测 |
| --- | --- |
| 冷构建 | crate 1m15s + runner 2m2s ≈ 3.5 分钟 |
| 增量构建 | 1.5–3 秒 |
| 产物 | 50 MB `.app` / 17 MB zip |
| 裁剪 | ❌ 无效。`nsh-cli` 生成的 runner 硬编码 `features = ["shader","editor","emoji-picker","highlight","math","plot","rich-editor","term"]`，`Cargo.toml` 里 `default-features = false` 不起作用 |

对比：EcoPaste（Tauri）dmg 9.9–10.3 MB，exe 5.8–6.6 MB。nsh 体积劣势明显，属于可接受代价。

## 二、窗口与焦点

`WindowKind::Popup` 在 macOS 上是 `NSPanel`，带 `NSWindowStyleMask::NonactivatingPanel`，CGWindowLayer = 3（floating）。

**不抢焦点**（14 次采样、覆盖弹出时刻，前台应用恒为原应用）：

```
front before = paste_target
front after  = paste_target      panel onscreen=1
```

对照实验（只把 `activate` 换成 `Some(true)`）：前台在第 4 秒切成本应用 → 证明测量方法有效，且默认行为确实抢焦点。

**键入焦点**（关键修复）：

| | 修前 | 修后 |
| --- | --- | --- |
| 弹出后直接敲 `x` | 进了前台应用（`TEXT=[x]`） | 面板收到（`PANEL key x received`），前台 `TEXT=[]` |
| 是否需先点一下面板 | 需要 | 不需要 |
| Esc 收起 | 不可用 | `PANEL open=false reason=Escape` |
| 失焦收起 | 不可用 | `PANEL open=false reason=Blur` |

修法：`open` 信号置 true 后，用 `set_timeout(120ms)` 再调 `WindowRef::focus()`。原因是窗口在 commit 后才创建，同拍调用落空。

> ⚠️ **P2 复测推翻了这一条的一半**（2026-11-15 下午）：`activate = Some(false)` 时窗口收不到键盘。实测 `key=None active=false`——`focus()` 从非主线程调用（`set_timeout` 的回调里 `MainThreadMarker::new()` 返回 `None`），`makeKeyAndOrderFront` 是空操作；而 app 不 activate 时窗口也成不了 key window。现行做法见第九节：**`activate = Some(true)` + 粘贴时切回原应用**，并要求 `focus()` 走 `run_on_main_thread`。

nsh 源码依据：`NshPanel::canBecomeKeyWindow` 由 `focusable` 属性驱动（注释：*"a borderless panel cannot be key by default"*），`order_front()` 在 `activate = false` 时走 `Activation::None`（不激活应用）但仍执行 `makeKeyAndOrderFront`。

## 四、剪贴板

用 `clipboard-rs 0.3`（与 EcoPaste 同一底层），在 nsh 应用内直接可用，不需要 Tauri。

```
CAPTURE cc=70 flavors=text :: AAA-plain
CAPTURE cc=73 flavors=html+text :: <b>BBB-rich</b> <i>html-flavor</i>
CAPTURE cc=76 flavors=rtf+text :: {\rtf1\ansi\ansicpg936...
CAPTURE cc=79 flavors=image ::
CAPTURE cc=82 flavors=files :: /etc/hosts|/etc/passwd
```

| 项 | 实测 |
| --- | --- |
| 轮询间隔 | 120 ms（`NSPasteboard.changeCount`） |
| 捕获延迟 | min 71 / median 128 / max 134 ms |
| CPU / RSS | 1.2% / 89 MB |

## 五、回环抑制与自动粘贴

```
CAPTURE cc=107 flavors=text :: CHAIN-PASTE-OK
WRITEBACK cc=108 expect SKIP next
AUTOPASTE cmd+v posted ok=true         # 进程内 CGEvent(core-graphics 0.25)
SKIP self-write changeCount=108
```

目标应用实测收到 `TEXT=[CHAIN-PASTE-OK]`，整链（捕获 → 写回 → ⌘V → 目标应用）成立。

## 六、权限

- 合成按键 / CGEvent 需要辅助功能授权，未授权时 `AXIsProcessTrusted() = false`，`osascript key code` 报错 `1002`
- 授权后 `axTrusted=true`，进程内 `CGEvent` 可正常发送
- 引导入口可用：`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`

## 九、P2 面板（2026-11-15 下午，clipnest 产品化第一版）

面板 = 搜索框 + 历史列表 + 键盘操作（↑↓ 选择、⏎ 粘贴、Esc 收起）。

### 9.1 键盘链路的三个必要条件（缺一个就打不了字）

| 条件 | 依据 | 不做会怎样 |
| --- | --- | --- |
| 窗口 `activate = Some(true)` | `NSApp.active=true` 才有 key window | `key=None active=false`，按键全被前台应用吃掉 |
| `focus()` 从**主线程**发出 | `set_timeout` 回调里 `MainThreadMarker::new() == None`；非主线程调 AppKit 是空操作 | 日志 `PANEL focus try=N key=None active=false`，重试到放弃 |
| 输入框 `auto_focus(true)` | 输入框在窗口隐藏时渲染，靠它拿 field editor | 窗口成 key 但字符进不了 `input().on_change` |

实测成功的日志：

```
FRONT remember pid=699                     # 打开面板前记下前台应用
PANEL focus try=0 key=Some("") active=true # 窗口成了 key
SEARCH q="hello" rows=1                    # 字符进到了搜索框
```

进不去键盘的原因顺序排查（都是实测过的坑）：

1. `PANEL focus try=N key=None active=false` → 没 `activate`，或 `focus()` 不在主线程
2. `key=Some(...) active=true` 但仍无字符 → `input` 没拿到 field editor（`auto_focus` 缺失 / 被后来的 `focus()` 打断）
3. 手动再 `focus()` 一次输入框反而**丢输入**（field editor 重挂），别画蛇添足

### 9.2 焦点在输入框里时的按键归属

- **Esc 被 `input` 吃掉**，`WindowKind::Popup` 自带的 `close_on_escape` 收不到。要自己绑 `on_key_with("escape", When::Always, || dismiss())`。
- 方向键同理：单行 `input` 会消费 ↑↓，必须 `When::Always`（`KeyOptions { when: Always, repeat: true, pass_through: false }`）。
- ⏎ 用 `input().on_submit(...)` 就够（`on_key("enter")` 在输入框聚焦时不会触发，别双绑以免粘两次）。

### 9.3 粘贴：面板会抢走前台，必须切回去

打开面板（`activate=true`）后前台应用变成 clipnest。所以粘贴是四步：

```
写回剪贴板 → dismiss()（隐藏面板 + activate 原应用）→ 120 ms → CGEvent ⌘V
```

- 原应用 pid 由 `NSWorkspace::sharedWorkspace().frontmostApplication()` 在**打开面板之前**记下（`clipboard::remember_front_app`）
- ⌘V 必须等切回生效后再发（沿用 P0 的 120 ms）
- 放弃（Esc / 失焦）也走 `dismiss()` 的切回逻辑，否则用户被留在面板里
- 回环抑制照旧：写回后登记 changeCount，watcher 见到 `SKIP self-write`

端到端实测（前台是 `tools/paste_target.swift`）：

```
SEARCH q="hello" rows=1
PASTE id=2 kind=text cc=142
FRONT activate pid=699 ok=true
SKIP self-write changeCount=142
AUTOPASTE cmd+v posted ok=true
目标窗口收到 TEXT=[面板测试 第二条 hello]
```

### 9.4 其它实现坑

- **列表必须包 `dynamic(|| ...)`**：`view().children(items.iter().map(...))` 是静态快照，搜索后列表不刷新（底部那行计数是响应式的，会显示 1/N 而列表还是首帧，极易误判）。
- **`#[component] fn Panel()` 的构造器是小写 `panel()`**，不是 `Panel()`（宏生成 `PanelElement` + `panel()`）。
- 每次打开面板要清空查询并重查：面板窗口是「隐藏/显示」而非重建，组件的 signal 会留着上次的搜索词。
- nsh 的 `run_app` 总会开一个主窗口：常驻应用要在根组件里 `current_window().hide()` 掉（`MAIN window hidden id=main main=true`）。
- 合成打字（`tools/keys3.swift type:...`）每个字符必须**新建** `CGEvent` 并用 `.combinedSessionState`；复用/`.hidSystemState` 时字符不进输入框（同一次会话里 `x` 能进、`hello` 不能）。

## 十、托盘与设置窗（P2 后半）

### 10.1 托盘

```rust
tray().icon(ImageSrc::svg_markup(SVG)).tooltip("…").title([TrayTitleRun::new("❐")])
      .menu(vec![MenuItem::new("显示面板").on_select(..), MenuItem::new("偏好设置…").on_select(..),
                 MenuItem::separator(), MenuItem::new("退出 clipnest").on_select(..)])
      .on_click(move |_| toggle())
```

实测：

```
TRAY attached
# 点菜单栏 ❐：System Events 报 "menu bar item ❐ of menu bar 2 of application process nsh-app-clipnest"
PANEL toggle before=false after=true
PANEL rows=2
```

坑：

- **菜单栏里 16 pt 的纯图标很难确认也没法自动化点**，所以配一个 `title` 字符（`❐`）——`System Events` 能按名字找到它，也能直接报坐标。
- `on_click` / `on_select` 的回调线程不确定，回调里只能碰 `static`（见 10.3）。
- 图标用内联 SVG：macOS 当模板图，笔画颜色用 `black`，只认不透明度（用其它颜色会变实心/不可见）。

### 10.2 设置窗（`WindowKind::Dialog`）

540×340，`input` 直接绑设置字段，改一项存一项（`settings.json` 原子写：先 `.tmp` 再 rename）。

实测：

```bash
echo '{"max_items":1,"panel_height":420}' > $CLIPNEST_DATA_DIR/settings.json
# 启动
PRUNE startup removed=1 max=1          # 启动补给：按上限裁到 1 条
# 面板高度改 600 后重启，窗口 bounds 实测 Height=600
```

坑：

- 坏 json / 缺字段要用默认值兜底（`#[serde(default)]` + 解析失败记日志），否则用户手改坏一次应用就起不来。
- 受控 `input`（`.value()` 绑 signal）在 `on_change` 里必须同时更新那个 signal，否则输入被回滚到旧值。
- 窗口尺寸在创建时给，改设置只能「下次启动生效」——UI 上要写明，不然像 bug。

### 10.3 跨线程：`Signal` 要放 `static`

`set_timeout` / 托盘菜单的回调可能不在主线程，而 `thread_local!` 是「每线程一份」：
把面板 `open` 信号放 thread_local 时，从定时器里读到的永远是 `None`（设置窗根本打不开）。

结论：`static OPEN: OnceLock<Signal<bool>>`（`Signal` 是 `Copy + Send + Sync`），
`thread_local` 只留真正与 UI 线程绑定的东西（`WindowRef`、`ElementRef`）。

## 十一、条目动作（P2 收尾）

键位与实测（面板内，焦点在搜索框里也生效，全部 `When::Always`）：

| 键 | 动作 | 实测日志 |
| --- | --- | --- |
| `⌘1`–`⌘9` | 直接粘贴第 N 条 | `PASTE id=1 kind=text` → `FRONT activate pid=… ok=true` → 目标收到 `TEXT=[测试 动作A]` |
| `⌘D` | 删除当前条 | `DELETE id=4` |
| `⌘P` | 置顶切换（`update_meta`，不动 `updated_at`） | `PIN id=4 -> true` |
| `⌘S` | 收藏切换 | `FAV id=4 -> true` |
| `⌘Y` | 复制到剪贴板但不粘贴 | `COPY id=4 cc=160` |
| `↑`/`↓`/`⏎`/`Esc` | 选择 / 粘贴 / 收起 | 见第九节 |

### 11.1 三个必须记住的坑

1. **`⌘⇧C` 这类 shift 组合到不了 keymap**：`on_key_with("mod+shift+c", When::Always, …)` 不触发（`osascript` 与进程内 CGEvent 都试过），而 `⌘P`/`⌘S`/`⌘D`/`⌘Y` 全部正常。复制改用 `⌘Y`（yank）。
2. **`close_on_blur` 会把面板自己关掉**：删条目/置顶后 rows 变化 → 重渲染 → 搜索框的 field editor 重挂 → 窗口收到 blur → 面板关闭（日志 `PANEL open=false reason=Blur`，前台还是自己）。现在 `close_on_blur = Some(false)`，只认 Esc；`SPIKE_CLOSE_ON_BLUR=1` 可以切回旧行为对照。
3. **主窗口不能 `hide()`**：主窗口一隐藏，应用就不算 active，面板永远成不了 key window（`key=None active=false`，键盘全被前台应用吃掉）。改成「去掉标题栏 + 透明 + 挪到屏幕外 + 点击穿透」——系统最多只让窗口移出到 `x=-380`（还留 40pt），所以透明和 `pointer_events: None` 是必须的。

### 11.2 列表要用 `each`

- 静态 `children(...)`：不刷新（底部响应式计数正常，最容易被骗）。
- `dynamic(|| …)`：能刷新，但整块重建，删一条就触发上面第 2 条的失焦关窗。
- `each(rows, |r| r.id, |row, i| …)`：按 key 只增删变化的那一行，删除后焦点还在搜索框。

附带一个 Rust 细节：行渲染函数要返回具体类型 `View` 而不是 `impl IntoElement`，否则在 `each` 的闭包里返回会把 `&Row` 的生命周期带出去（E0515）。

## 九、Windows 交叉编译（2026-11-15 补测）

原判断「macOS 无法交叉编译」已被推翻。环境：卸载 brew rust → 官方 rustup → `rustup target add x86_64-pc-windows-msvc` → `cargo install cargo-xwin`（0.23.1）。

| 步骤 | 结果 |
| --- | --- |
| `cargo xwin check --target x86_64-pc-windows-msvc` | ✅ 全仓通过 |
| `cargo xwin build --release --target x86_64-pc-windows-msvc` | ✅ 1m48s；`nsh-app-clipnest.exe` 43 MB，PE32+ GUI x86-64 |
| `nsh package --target windows` | ✅ 2m5s；`.nsh/out/clipnest.zip` 20 MB + `.nsh/out/clipnest/`（exe + nsh/app.json） |
| Inno Setup 安装包 | ⚠️ 只生成了 `clipnest.iss`，打 `.exe` 安装包需 Windows 侧装 Inno Setup 6 |

导入表（`llvm-objdump -p`）：`d2d1.dll`、`dwrite.dll`、`d3d11.dll`、`dxgi.dll`、`dcomp.dll`、`dwmapi.dll`、`comctl32.dll`、`bcrypt.dll`、`api-ms-win-crt-*`
→ 确认 Windows 后端是 Win32 + Direct2D/DirectWrite，UCRT 用系统自带（Win10+ 无需 VC 运行库）。

### Windows 后端的 API 差异（本次编译暴露）

`nsh-platform-windows 0.5.1` 的 `AppOptions` 只有 12 个字段，缺 macOS 有的：

- `keep_alive_on_close`（关窗常驻）
- `activation_policy`（accessory 菜单栏形态）
- `background`（`NSApplicationActivationPolicyProhibited` 等价物）
- `display` / `keep_size` / `chunks` / `host` / `limits`

已处理：`src/main.rs` 里这些字段用 `#[cfg(target_os = "macos")]` 门控（原先直接写在结构体里导致 Windows 编译失败）。
**含义**：Windows 上的「托盘常驻 + 不抢焦点」形态不能照搬 macOS，必须在真机验证，属于路线图 R1 的新增子风险。

### 结论

编译与打包不再是 Windows 侧的阻塞项：Mac 出 zip → 拷到 Windows 解压双击即可冒烟，无需在 Windows 装 Rust/VS/nsh。
仍必须真机验证的：Popup 是否抢焦、`RegisterHotKey` 触发、剪贴板事件驱动路径、`SendInput` 粘贴、托盘图标、多显示器定位。

## 十四、图片条目与缩略图（P3 第一项）

### 14.1 落库链路

```
剪贴板 image flavor
  → clipboard::capture：编码成 PNG（ImageBytes{png,width,height}）
  → store::record：文件名 = blake3(png bytes) + ".png"
      images/origin/<hash前2>/<hash>.png      原图（字节原样写入）
      images/thumbnails/<hash前2>/<hash>.png  等比缩到 320 以内的缩略图
  → items：kind=image，content="<hash>.png"，width/height 记像素尺寸
```

去重靠内容哈希：同一张图再复制一次不会写新文件，只涨 `use_count`。图片优先于文本
（复制截图时系统同时给文本/位图 flavor，只留图片条目）。

### 14.2 关键坑：macOS 截图只给 TIFF，而 clipboard-rs 只开 png/jpeg 解码

`clipboard-rs 0.3` 的 `image` 依赖 `features = ["png", "jpeg"]`，`get_image()` 在 macOS 上
先找 `public.png`，没有就拿 NSImage 的 `TIFFRepresentation` 交给 `image::load_from_memory`
——TIFF 解不了：

```
IMAGE decode 失败 type=public.tiff bytes=135398
DB SKIP 无可入库内容
```

兜底（`clipboard::read_pasteboard_image`）：只有 TIFF 时走系统 API 重新编码

```
NSPasteboard.dataForType("public.png")            // 有就直接用
NSImage::initWithPasteboard → TIFFRepresentation
  → NSBitmapImageRep::initWithData
  → representationUsingType_properties(NSPNGFileType)
```

即让 AppKit 解码，只用 `image` crate 读生成的 PNG 拿尺寸。`image` 依赖因此仍是 `png`
（`tiff` 也开着，但不再依赖它解码 NSImage 的输出）。

### 14.3 实测

```bash
swift tools/pb.swift image            # 64pt 粉色方块（写的是 TIFF）
# CAPTURE cc=192 flavors=image :: <图片 128×128>
# DB INSERTED id=1 kind=image

sqlite3 $CLIPNEST_DATA_DIR/clipnest.db \
  "select kind,content,width,height from items"
# image|1a4d8b8f….png|128|128
ls -l images/origin/1a/ images/thumbnails/1a/
# origin 38.2K / thumbnails 3.8K   ← 缩略图确实变小

# 面板：行内 28pt 缩略图 + "图片 128×128"
# 回车粘贴：
# PASTE id=1 kind=image cc=193 → AUTOPASTE cmd+v posted ok=true
# 剪贴板里能读回 PNG：`«data PNGf89504E47…»`
```

`src/keys.rs` 一处定义，面板底部提示、行内 `1`–`9` 序号、设置窗都从这里取：

| | macOS | Windows |
| --- | --- | --- |
| 唤出 | `⌘⇧V` | `Ctrl+Shift+V` |

## 十五、多显示器定位（P3）

面板打开时摆到**鼠标所在那块屏**的中央。

### 15.1 关键坑：`desktop::displays()` 不能在主线程回调里调

第一版用 `nsh_core::element::desktop::displays()` 找鼠标所在屏、再 `panel.center(Some(id))`：

```
thread 'main' panicked at nsh-core/src/element/reactive.rs:164:
no reactive runtime: signals are used on the engine thread, while components run
```

它读的是 nsh 的响应式环境，而 `run_on_main_thread` 的回调不在那个环境里。
所以改成**自己问系统要屏幕区域、只算窗口坐标**，再 `WindowRef::set_bounds`：

```rust
// macOS：NSScreen::screens() 里找包含鼠标的那块，NSEvent::mouseLocation() 是左下原点
// Windows：GetCursorPos → MonitorFromPoint → GetMonitorInfoW(rcWork)
let (x, y) = cursor::panel_origin(PANEL_WIDTH, panel_height)?;
panel.set_bounds(WindowFrame { x: Some(px(x)), y: Some(px(y)), ..Default::default() });
```

### 15.2 坐标翻转

nsh 的屏幕坐标是左上原点、y 向下；`NSScreen.frame` 是左下原点、y 向上。
换算：`top = 主屏高度 - (frame.origin.y + frame.height)`。副屏在主屏左边时 x 为负，纯函数
`center()` 已覆盖这三种情况（主屏居中、负坐标副屏、屏幕比面板还小）。

### 15.3 实测

```
PANEL toggle before=false after=true
PANEL at=Some((615.0, 346.0))        ← 主屏 1710×1112 里居中放 480×420
PANEL focus try=0 key=Some("") active=true
CGWindowList: layer=3 bounds X=615 W=480 H=420
```

Windows 侧同一份代码用 `GetCursorPos + MonitorFromPoint + GetMonitorInfoW`，交叉 `cargo xwin check` 通过（多屏行为待真机确认）。

## 十六、敏感应用过滤（P3）

按**应用身份**过滤，不猜内容：密码管理器里复制的直接丢，不写库、不落图片文件。

### 16.1 三层控制

| 层 | 位置 | 作用 |
| --- | --- | --- |
| 内置白名单 | `sensitive::DEFAULT_APPS` | 1Password / Bitwarden / KeePassXC / KeePass / LastPass / Dashlane / NordPass / Enpass / Proton Pass / 系统钥匙串 |
| 设置覆盖 | `settings.json` 的 `sensitive_apps`（非空即以它为准）、`ignore_sensitive_apps`（总开关） | 名单可自定义；也能整体关掉 |
| 单条手动 | 面板 `⌘E` | 标记/取消标记任意一条，行上显示 🔒；走 `update_meta`，不动 `updated_at` |

名单项大小写不敏感、去掉 `.exe`；命中规则是「相等 / 以 `名单项.` 开头 / 以 `.名单项` 结尾」——
最后两条专门为 macOS 的 `com.1password.1password.helper` 这类子进程，裸 `ends_with` 会误伤（`notkeepassxc`）。

> 特意**不**把 `com.apple.safari` 放进去：Safari 里复制普通文本太常见，拦了等于废掉一半历史。

### 16.2 实测

```bash
# 把前台应用（kitty）临时加进名单
printf '{"sensitive_apps":["net.kovidgoyal.kitty"],"ignore_sensitive_apps":true}' > $CLIPNEST_DATA_DIR/settings.json
swift tools/pb.swift text "密码应该被拦截"
# SKIP sensitive app=net.kovidgoyal.kitty
# 库里条数不变（4）

# 单条标记
⌘E → SENS id=4 -> true
# 面板首行出现 🔒，底部提示 "⌘E 敏感"
```

### 16.3 一个 `each` 的坑

`each(rows, |r| r.id, …)` 只用 id 当 key，改置顶/收藏/敏感**不会重画**（行内容是一次性快照）。
key 要带上会影响显示的可变字段：

```rust
|row: &Row| (row.id, row.pinned, row.favorite, row.sensitive,
             row.summary.clone(), row.time.clone())
```

代价是这些字段变了整行重建，可接受（一次按键一行）。

## 十七、权限引导与开机自启（P3）

### 17.1 权限引导

面板顶部：`clipboard::ax_trusted()` 为 false 时出现一条提示「没有辅助功能权限：回车不会自动粘贴」+
「打开设置」按钮（`open_url("x-apple.systempreferences:…Privacy_Accessibility")`）。
Windows 上 `ax_trusted()` 恒 true，这条不出现。

自检开关：`SPIKE_NO_AX=1` 假装没授权，用来验这条 UI（截图见 `/tmp/panel-ax.png` 那次的形状）。

### 17.2 开机自启

| | macOS | Windows |
| --- | --- | --- |
| 载体 | `~/Library/LaunchAgents/com.example.clipnest.plist` | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` |
| 判据 | plist 文件存在 | 注册表值存在 |
| 内容 | `ProgramArguments` = `current_exe()`，`RunAtLoad` | `"<exe 绝对路径>"` |

**坑：不要 `launchctl load -w`**。plist 里有 `RunAtLoad`，一 `load` 就**立刻再起一个实例**
（实测 `pgrep` 变成 2 个）。只写文件即可——登录时 launchd 自己会扫描 `~/Library/LaunchAgents`。
关闭时删文件（顺带 `launchctl unload` 容错）。

实测：

```
SPIKE_AUTOSTART=on
AUTOSTART set=true now=true path=Some("~/Library/LaunchAgents/com.example.clipnest.plist")
# plist 里 ProgramArguments 指向 target/debug/nsh-app-clipnest；实例数仍是 1
launchctl list | grep clipnest   → 没有再起一个

SPIKE_AUTOSTART=off
AUTOSTART set=false now=false    → plist 已删，launchctl 也无记录
```

设置窗里「开机自启」是一个开/关按钮，点了立刻写/删，并回显真实状态（`is_enabled()` 复查一次，
不是只信自己写成功）。

## 十八、拖拽导出：nsh 没有这个能力，降级为「导出 + 粘文件」

### 18.1 结论：nsh 0.5.1 只能**接收** drop，不能**发起**拖拽

- `nsh-platform-macos/src/file_drop.rs` 实现的是 `NSDraggingInfo` 的 target 一侧（`draggingEntered` / `performDragOperation`）。
- `nsh-core` 里没有 `draggable()` / `beginDraggingSession` 之类 API。
- `WindowRef` 也不暴露 `NSView`（只有 `set_bounds` / `focus` / `center` / `set` 这些命令式接口），拿不到拖拽源视图。

真拖拽需要三样：面板的 `NSView`、当前鼠标拖动事件、拖拽内容。我们只有最后一样。
三条路线：打补丁 vendored nsh（升级要重打）、`NSApp.windows()` 里认窗口 + `on_pan_start` 自己发起
（在别人的事件流里插一手，脆弱）、等上游。

### 18.2 采用的做法：导出成文件 + 放剪贴板

`⌘O`：

```
EXPORT id=1 files=~/Downloads/clipnest-20261115-221850.png cc=204
```

- 文本 → `.txt`，HTML → `.html`，RTF → `.rtf`，图片 → 直接拷 `images/origin/<hash>.png`（不重新编码）
- `files` 条目不用导出：本来就在磁盘上，直接把它们的路径放进剪贴板
- 导出后把路径 `set_files` 进剪贴板，于是紧接着 `⌘V` 到 Finder / 微信 / 邮件粘出来的就是文件
- 导出目录：`settings.export_dir`，空则 `~/Downloads`

### 18.3 两个实测坑

1. **写剪贴板文件后前台会被抢回原应用**：面板还在屏上但拿不到键盘，后续快捷键全失效。
   导出成功后补一次 `focus_panel()`（复用 `focus_when_ready`）解决——实测连按两次 `⌘O` 都能出文件。
2. **小图的缩略图不要用 `image` 重编码**：128×128 的图 AppKit 编码是 3.8K，`image` crate 重编码出来 39K
   （比原图大 10 倍，等于把缩略图目录变成更大的副本）。现在只在最长边 > 320 时才真缩，否则直接拷原图字节。

## 十九、同步配置与后端（P4 前半）

### 19.1 配置文件：独立的 `sync.json`

放数据根目录（与 `settings.json` 平级），**不塞进主设置**：开源项目要能单独给模板、单独写文档、
单独迁移版本，也不让「钥匙串条目名」这类东西混进 UI 偏好。

```json
{
  "version": 1,
  "enabled": true,
  "device_name": "mac-a",
  "backend": { "kind": "local_dir", "path": "/Volumes/NAS/clipnest" },
  "encryption": { "enabled": true },
  "interval_secs": 1800
}
```

- 后端是 serde 的 internally-tagged 枚举：`kind` 判别，加 S3/SFTP 只加一个变体，
  旧配置里的未知字段被忽略（`unknown_fields_are_tolerated` 有测试）。
- `normalized()` 兜底：设备名变成安全文件名（`MacBook Pro / 家里` → `MacBook-Pro-----`），
  WebDAV 地址去尾斜杠、远端目录补前导斜杠。
- WebDAV 变体要显式 `#[serde(rename = "webdav")]`：`rename_all = "snake_case"` 会把它写成 `web_dav`（踩过）。

### 19.2 凭据：系统钥匙串

| | 存哪 | 实现 |
| --- | --- | --- |
| 同步口令 | macOS Keychain / Windows 凭据管理器 | `security-framework` / `CredWriteW` |
| WebDAV 密码 | 同上（服务名 `clipnest-webdav`，账号＝用户名） | 同上 |

`sync.json` 里**没有**任何口令字段（有测试断言序列化结果不含 `password`）。
UI 里口令是「输完回车存进钥匙串」，输入框不回显已保存的值，只显示「已保存（改就重输）」。

> Windows 侧踩到一个真 bug（clippy 抓的）：`cred.UserName = wide(account).as_ptr()` 把临时 `Vec<u16>`
> 在语句结束时丢掉了，指针悬垂。改成先绑一个变量活到调用结束。

### 19.3 传输层

`Transport`（`list/get/put/remove`）两个实现：

- `LocalTransport`：本地/挂载目录（网盘同步盘、移动硬盘都算），零部署。
- `WebDavTransport`：`PROPFIND Depth:1` 列目录（自己抠 `<d:href>`，不引 XML 依赖）、`GET`/`PUT`/`DELETE`，
  Basic 认证头自己拼（最简 base64，有单测）。目录不存在时 `MKCOL` 建一次。

已知限制：`insecure_tls` **暂不生效**（ureq 的 rustls 没有跳过校验的简单开关），启动时打日志提示
「给 NAS 装有效证书，或改用 local_dir」。这条写进文档，不假装支持。

### 19.4 合并规则

| 情况 | 结果 |
| --- | --- |
| 本地没有该 `content_hash` | 插入（原样带 `use_count`/时间戳/标记） |
| 两边都有 | `updated_at` 新的赢；`use_count` 取 **max**（重复拉取不膨胀） |
| 本地墓碑比来件新 | 跳过（不会被旧数据复活） |
| 删除 | 墓碑带 `deleted_at` 传播；本地 `updated_at <= deleted_at` 才删 |
| 分组 | 按**名字**对齐，不照搬 id |

### 19.5 实测（两台"设备"用本地目录当远端）

```bash
/tmp/clipnest-remote/mac-a.json        ← 增量包
```

## 二十、真 NAS 的 WebDAV 联调（飞牛 fnOS，2026-11-15）

环境：`https://192.168.110.94:5006`，飞牛 fnOS，WebDAV 在 5006 端口，**自签证书**（`CN=fnOS`），
HTTP/2 + Basic 认证（`WWW-Authenticate: Basic realm="Restricted"`）。

### 20.1 踩到的四个坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `PROPFIND not valid for HTTP version HTTP/1.1` | **ureq 的协议层只允许标准方法**（`ureq-proto` 的 `verify_version`），发不出 PROPFIND/PROPPATCH/MKCOL | 换 `reqwest`（blocking + rustls + http2），`Method::from_bytes` 支持任意方法 |
| 每个请求卡到 20 秒超时 | 本机有 `HTTPS_PROXY=127.0.0.1:7892`，reqwest 默认读环境代理，把局域网 IP 也送进了代理 | `Client::builder().no_proxy()` |
| 上传图片回 **403** | fnOS 在「父目录不存在」时回 **403**（不是标准的 409，也不是 404） | `put()` 把 403/404/409 都当「父目录没有」，先 `MKCOL` 再重试 |
| `/clipnest` 建不出来 | 根目录**只读**：`MKCOL /clipnest/` 和 `PUT /probe.txt` 都 405，但 `PUT /data/…` 是 201 | `remote_dir` 用可写目录 `/data/clipnest` |

根目录下的可写目录（PROPFIND `Depth: 1` 看到的）：`/data/`、`/个人资料/`、`/影视/`。

### 20.2 实测数据

```bash
# 探针（只读）：列目录 + 写读删一个测试文件
WEBDAV_URL=https://192.168.110.94:5006/data/clipnest/ WEBDAV_USER=nekoleamo \
  cargo test live_webdav_probe -- --ignored --nocapture
list OK: ["mac-a.json"]           ← 0.1 s
get mac-a.json: 2080 字节, 10.5ms
put OK / get Ok / remove Ok

# 第一台设备：全量推送（4 条文本 + 1 张图，加密载荷）
SYNC ok pushed=5 pulled=0
# 远端：/data/clipnest/mac-a.json（2.0 KB 密文，magic CNST1）
#       /data/clipnest/blobs/1a/<hash>.png（原图）

# 第二台设备：空库拉取
SYNC ok pushed=0 pulled=5 +5 ~0 -0
# 图片也下来了：images/origin/1a/<hash>.png + thumbnails/…（缩略图自动补生成）

# 增量（mac-a 新复制一张图）
```

### 20.3 性能观察

- 增量单条推送：几秒（含 TLS 握手 + argon2 派生）。
- 首轮全量（5 条 + 39 KB 图片）：约 1~2 分钟，其中大部分是首次连接建立与图片下载；
  同一会话内的请求都在 10–50 ms。超过 500 ms 的请求现在会打 `SYNC slow <method> <url> <status> <ms>`，
  下次觉得慢直接看这条日志。
- 现在也接上了定时同步：`sync.json` 的 `interval_secs >= 60` 时自动跑（改完重启生效）。

### 20.4 当前状态与遗留

- NAS 上已有 `mac-a.json` 与 `blobs/`（我的联调数据），可以直接删掉重来。
- 同步口令目前是联调时写进钥匙串的临时值（服务名 `clipnest-sync`、账号＝设备名），正式用请换掉。
- 委托给 `Transport` 的能力仍只有 `list/get/put/remove`，S3/SFTP 照这个接口加即可。

## 二十一、图片文件回收（P4 收尾）

数据库删了、`images/` 里的文件还在，是同步与清理都会踩的坑。现在三条路都清：

| 触发 | 做什么 |
| --- | --- |
| 面板 `⌘D` 删条目 | `store::remove` → 删行 + 删该图的 `origin/` 与 `thumbnails/` |
| 按上限裁剪（启动 / 改设置 / 手动清理） | `prune` 先取要删的 id，再逐个 `remove`（连带文件） |
| 启动时扫一遍孤儿 | `collect_garbage`：`images/` 里没有对应条目的 png 直接删（历史遗留、导入失败的残留） |

图片文件名就是内容哈希，一张图只有一条记录、一组文件，所以按 hash 删不会误伤别的条目。

实测：

```
# 采集一张图 → 2 个文件（原图 + 缩略图）
find images -name "*.png" | wc -l   → 2
# 手动塞一个没有记录的孤儿
IMAGE gc startup removed=1          ← 启动时清掉
# 面板 ⌘D 删这条图片
DELETE id=1
find images -name "*.png" | wc -l   → 0     ← 原图与缩略图一起没了
```

远端 `blobs/` **不删**：多设备共享同一份图片，删一边的文件会让另一台在补拉时 404。
tombstone 已经保证对端的记录会被删，图片文件留着只是占空间，属于可接受的取舍（要彻底的话得做引用计数 + 增量 GC，P6 再说）。

## 二十二、签名与公证：不花钱能做到哪一步

### 22.1 结论

| 项 | 花钱？ | 没有会员时的效果 |
| --- | --- | --- |
| 代码签名（ad-hoc 或自签） | 免费 | 能签上，但身份不被 Gatekeeper 信任，等于没签 |
| Apple Development 证书（免费 Apple ID / Personal Team） | 免费 | 7 天过期、最多 3 台设备，只能自己调试，不能分发 |
| **Developer ID + 公证（notarization）** | **付费会员** | 拿不到 Developer ID 证书，`notarytool` 无法提交 |

本机现状（实测）：

```
codesign -dv .nsh/out/clipnest.app
  Signature=adhoc, flags=0x2(adhoc)      ← nsh 打包默认就是 ad-hoc 签名
spctl -a -vvv .nsh/out/clipnest.app
  accepted, override=security disabled   ← 本机 Gatekeeper 是关的，测不出拦截效果
```

Apple 官方会员对比页（`developer.apple.com/support/compare-memberships/`）里
**「Mac software notarization」列在付费/企业会员那一栏**；免费注册只给文档与 Personal Team，
且 Personal Team 的证书「expire after 7 days」「install up to 3 apps per device」。
价格（美国 $99/年、中国区约 ¥688/年）不在该页，以官网结账页为准。

### 22.2 零成本分发（已落地）

- `tools/release.sh`：测试 + 两平台 clippy `-D warnings` + 打 macOS/Windows zip + `SHA256SUMS` + 生成 cask
- `packaging/homebrew/clipnest.rb.template`：自建 tap 的 cask，`postflight` 里 `xattr -dr com.apple.quarantine`
- `docs/发布.md`：发版清单与「付费后要加什么」

实测一遍「用户拿到 zip 之后」：

```bash
ditto -x -k dist/clipnest-1.0.0-macos.zip /tmp/user-install
xattr -w com.apple.quarantine "0081;6af9d26f;Safari;" /tmp/user-install/clipnest.app   # 模拟从浏览器下载
xattr -dr com.apple.quarantine /tmp/user-install/clipnest.app                          # cask postflight 做的事
/tmp/user-install/clipnest.app/Contents/MacOS/clipnest &
# BOOT pid=58047 … db=~/Library/Application Support/clipnest/clipnest.db
# TRAY attached
```

即：**删掉 quarantine 后直接可运行**。官方 homebrew-cask 要求已公证所以收不了，
但自建 tap 没有审核，这就是零成本路线能站住的原因。

> 本机 Gatekeeper 处于关闭状态（`override=security disabled`），所以「未删标记时会被拦」
> 这一半没法在本机复现——那条结论来自 Apple 文档与公开资料，不是实测。

### 22.3 付费后要补的三行

```bash
codesign --force --deep --options runtime --timestamp \
  --sign "Developer ID Application: <名字> (<TEAMID>)" .nsh/out/clipnest.app
xcrun notarytool submit dist/clipnest-<ver>-macos.zip --keychain-profile clipnest --wait
xcrun stapler staple .nsh/out/clipnest.app
```

签完 `spctl -a -vvv` 应显示 `source=Notarized Developer ID`，届时可以去掉 cask 里删 quarantine 那段，
也能提交官方 homebrew-cask。

## 二十三、不付费的自动更新链（P6）

### 23.1 关键判断

没有公证 ≠ 每次更新都要用户手动放行。Gatekeeper / SmartScreen 只检查**带下载标记**的文件
（`com.apple.quarantine` / Mark-of-the-Web），而浏览器才会打这些标记。应用自己下载、自己替换的
文件不带标记 → 首次放行一次之后，更新是「无感」的。

所以不付费的方案是：
1. **首次安装**：brew tap（cask 的 `postflight` 删标记，零拦截）或 zip（右键/系统设置放行一次）
2. **后续更新**：应用内自更新（`src/update.rs` + `nsh-updater`）

### 23.2 完整性靠自己的 ed25519 签名

`nsh keygen .keys/clipnest-release` → `.pub` 写进 `nsh.json` 的 `updater.publicKey`；
发布时 `nsh update-manifest --key .keys/clipnest-release.secret` 生成 `latest.json` + `latest.json.sig`。
应用侧 `Config::check(manifest, Some(sig), platform)` 验签后才认版本。

实测（用真实产物，把"当前版本"伪装成 0.0.1）：

```
cargo test signed_manifest -- --ignored
→ ok: 0.0.1 看到 1.0.0，asset 带 sha256/size
→ 篡改 manifest 一个字节 → Err（签名不匹配）
→ 不传签名 → Err（无签名一律不信）
```

### 23.3 两个平台的实际差异

| | macOS | Windows |
| --- | --- | --- |
| 首次安装拦截 | Gatekeeper：右键打开 / 系统设置「仍要打开」；brew 装则无 | SmartScreen「未知发布者」→「更多信息 → 仍要运行」 |
| 更新包 | `clipnest-<ver>-macos-aarch64.tar.gz`（nsh 打包时自动产出） | `clipnest-<ver>-windows-x86_64.zip`（同一份文件也当用户下载包） |
| 更新后 | 退出重开生效（替换的是 `.app`，进程仍跑旧映像） | 同上（nsh 会处理运行中的 exe 交换） |
| 是否仍被拦 | 不会（无 quarantine） | 不会（无 MOTW） |

### 23.4 落地的文件

- `src/update.rs`：`check()` / `install()` / `check_async()` / `install_async()` + 状态回显
- 设置窗「更新」行：检查更新 / 安装更新 + 状态文字
- `nsh.json` 的 `updater`（github + publicKey）
- `tools/release.sh`：打包后自动 `nsh update-manifest` 并签名
- `.keys/` 与 `dist/` 都在 `.gitignore` 里（私钥与产物不入库）

## 二十四、加密备份的界面（P6 前置）

`backup.rs` 一直是「实现了但用户摸不到」：argon2id + chacha20poly1305、round-trip、错口令拒绝都有测试，
但设置窗里没有入口。现在补上：

- 设置窗「备份」区块：备份口令（掩码，**只本次使用、不落盘**）、「导出备份」「导入最新」「打开 backups/」
- 导出写 `<数据根>/backups/clipnest-<YYYYmmdd-HHMMSS>.cnbak`，界面回显文件名与已有备份数
- 导入取 `backups/` 里最新的一份（文件名带时间戳，倒序即最新），回显「新增/跳过/分组」
- 备份口令与同步口令**是两回事**（后者在钥匙串里），不混用

实测（`SPIKE_BACKUP=export|import`，口令固定 test123）：

```
BACKUP SPIKE exported …/backups/clipnest-20261115-235642.cnbak    ← 2.0 KB, magic CNST1
# 拷到空库的 backups/ 再导入
BACKUP SPIKE imported inserted=5 skipped=0 groups=0
sqlite> select kind,count(*) … → image|1, text|4
```

### 顺带修的坑：`Signal::set` 在 `boot()` 里静默无效

`SPIKE_PREFS=1` 原本在 `boot()` 里 `set_timeout(3s, open_prefs)`，日志打出了 `PREFS set true`，
但设置窗**从来没出现**。原因：`boot()` 跑在 `run_app` 之前的纯函数上下文里，没有响应式运行时，
`Signal::set` 不触发重渲染。把自检挪进 `App()` 的渲染体（和 `SPIKE_AUTOOPEN` 一样）就好了。

结论：**`Signal::set` 必须在组件的渲染体/effect 里调用**；从普通线程改状态要走「写 static → UI 轮询」的模式
（同步/更新/备份的状态文字都是这么做的）。

## 二十五、界面返工：可读性 + 图片大图预览 + 面板贴底

用户实机用了两天后的反馈，三条都改了。

### 25.1 说明文字太暗

所有 `theme().muted_foreground` 的用法（设置窗的说明、面板的类型标签与时间、底部提示）在暗色主题下
读起来吃力。实测设置窗 hint 的像素是 `#A1A1A1`（对比度约 8:1），但 9pt 字号下仍然不醒目。

处理：**一律改用 `theme().foreground`**（暗色 `#FAFAFA`），层级靠字号（9/10/11pt）和间距区分，
不再靠颜色。同时把 hint 从 9pt 提到 10pt。

### 25.2 图片看不清 → 大图预览

列表行内的缩略图从 **28pt → 40pt**；选中图片条目时，搜索框下方出现 **240pt 高的大图预览**，
用原图（不是 320 的缩略图），等比缩放不裁切。

踩了两个坑：

1. **`image().object_fit(ResizeMode::Contain)` 实测没生效**（按 Cover 裁切了）。
   改成自己按 `items.width/height` 算显示尺寸：
   `scale = min(BOX_W/iw, BOX_H/ih).min(1.0)`（小图不放大，避免糊）。
2. 预览区用 `dynamic(|| ...)` 读 `rows`/`sel`，选中项一变就重建，切换即时生效。

`←`/`→` 与 `↑`/`↓` 同义（浏览图片时左右更顺手），都会带动列表滚动。

### 25.3 面板贴屏幕底部

需求是「像 Paste 那样在底部展示」。做法：`settings.panel_position` = `bottom`（默认）/ `center`，
设置窗里一个开关。

**位置只在窗口创建时生效**——这里有两个硬限制：

| 尝试 | 结果 |
| --- | --- |
| `WindowRef::set_bounds(WindowFrame { y })` 运行中挪窗口 | **完全无效**：探针把它设成 (10,10)，窗口纹丝不动停在 (615,249) |
| `window().default_position(WindowPosition::At(point(x, y)))` | 生效（窗口首帧就在目标位置） |
| 用 `NSScreen`/`NSEvent` 算位置 | **打包版的 `boot()` 不在主线程**，`MainThreadMarker::new()` 返回 `None`（日志 `PANEL at=None`），算出 None 就退回居中 |

所以最终实现：`default_position` + 只用 CoreGraphics 算坐标（`CGDisplay::main().bounds()` 任意线程可用），
底部时高度减 90pt 给 Dock 让位。代价是**不跟随鼠标所在屏**（多屏时面板总在主屏）。

实测：

```
PANEL at=Some((615.0, 438.0)) position=bottom
CGWindowList: layer=3 X=615 Y=438 H=560     ← 底边 998，Dock 上方
```

设置项文案写的是「改完下次启动生效」（窗口只创建一次），不是「下次打开」。

### 25.3.1 复盘：预览放右侧、提示放大

第一版把预览放在**列表上方**，选中图片时整块内容往下挤，视觉重心偏下。改成**左右分栏**：

```
[ 搜索框                          ]
[ 列表（flex_1）      ][ 预览 280 ]
[ 底部提示                        ]
```

- 面板宽度 480 → **720**（宽度也是窗口创建时定死，不能动态变）
- 竖图能撑满 280 宽的高度；横图受宽度限制（`scale = min(280/iw, H/ih)`）
- 底部提示 9pt → **11pt**：一行放得下需要缩短文案，
  现在是 `⏎ 粘贴 · ⌘D 删 · ⌘P 置顶 · ⌘S 收藏 · ⌘E 敏感 · ⌘O 导出 · ⌘Y 复制`（`⌘1-9 直贴` 保留）

截图确认：`X=495 Y=438 W=720 H=560`（屏幕 1710 宽居中、贴底）。

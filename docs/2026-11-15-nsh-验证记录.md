# nsh 可行性验证记录（2026-11-15，macOS）

验证工程即本仓库 `src/`（v0 骨架）。环境：macOS，Rust 1.100.0（Homebrew），nsh 0.5.1。

## 结论

macOS 侧技术路线成立，**不需要自建 AppKit 壳**。nsh 的 `WindowKind::Popup` 足够做剪贴板面板，唯一的缺口（收不到键盘）靠「延后一次 `focus()`」修掉。

## 一、打包与构建

| 项 | 实测 |
| --- | --- |
| 冷构建 | crate 1m15s + runner 2m2s ≈ 3.5 分钟 |
| 增量构建 | 1.5–3 秒 |
| 产物 | 50 MB `.app` / 17 MB zip |
| 裁剪 | ❌ 无效。`nsh-cli` 生成的 runner 硬编码 `features = ["shader","editor","emoji-picker","highlight","math","plot","rich-editor","term"]`，`Cargo.toml` 里 `default-features = false` 不起作用 |

对比：EcoPaste（Tauri）dmg 9.9–10.3 MB，exe 5.8–6.6 MB。nsh 体积劣势明显，属于可接受代价。

## 二、窗口与焦点

`WindowKind::Popup` 在 macOS 上是 `NSPanel`，带 `NSWindowStyleMask::NonactivatingPanel`，CGWindowLayer = 3（floating）。

**不抢焦点**（14 次采样、覆盖弹出时刻，前台应用恒为原应用）：

```
front before = paste_target
front after  = paste_target      panel onscreen=1
```

对照实验（只把 `activate` 换成 `Some(true)`）：前台在第 4 秒切成本应用 → 证明测量方法有效，且默认行为确实抢焦点。

**键入焦点**（关键修复）：

| | 修前 | 修后 |
| --- | --- | --- |
| 弹出后直接敲 `x` | 进了前台应用（`TEXT=[x]`） | 面板收到（`PANEL key x received`），前台 `TEXT=[]` |
| 是否需先点一下面板 | 需要 | 不需要 |
| Esc 收起 | 不可用 | `PANEL open=false reason=Escape` |
| 失焦收起 | 不可用 | `PANEL open=false reason=Blur` |

修法：`open` 信号置 true 后，用 `set_timeout(120ms)` 再调 `WindowRef::focus()`。原因是窗口在 commit 后才创建，同拍调用落空。

> ⚠️ **P2 复测推翻了这一条的一半**（2026-11-15 下午）：`activate = Some(false)` 时窗口收不到键盘。实测 `key=None active=false`——`focus()` 从非主线程调用（`set_timeout` 的回调里 `MainThreadMarker::new()` 返回 `None`），`makeKeyAndOrderFront` 是空操作；而 app 不 activate 时窗口也成不了 key window。现行做法见第九节：**`activate = Some(true)` + 粘贴时切回原应用**，并要求 `focus()` 走 `run_on_main_thread`。

nsh 源码依据：`NshPanel::canBecomeKeyWindow` 由 `focusable` 属性驱动（注释：*"a borderless panel cannot be key by default"*），`order_front()` 在 `activate = false` 时走 `Activation::None`（不激活应用）但仍执行 `makeKeyAndOrderFront`。

## 四、剪贴板

用 `clipboard-rs 0.3`（与 EcoPaste 同一底层），在 nsh 应用内直接可用，不需要 Tauri。

```
CAPTURE cc=70 flavors=text :: AAA-plain
CAPTURE cc=73 flavors=html+text :: <b>BBB-rich</b> <i>html-flavor</i>
CAPTURE cc=76 flavors=rtf+text :: {\rtf1\ansi\ansicpg936...
CAPTURE cc=79 flavors=image ::
CAPTURE cc=82 flavors=files :: /etc/hosts|/etc/passwd
```

| 项 | 实测 |
| --- | --- |
| 轮询间隔 | 120 ms（`NSPasteboard.changeCount`） |
| 捕获延迟 | min 71 / median 128 / max 134 ms |
| CPU / RSS | 1.2% / 89 MB |

## 五、回环抑制与自动粘贴

```
CAPTURE cc=107 flavors=text :: CHAIN-PASTE-OK
WRITEBACK cc=108 expect SKIP next
AUTOPASTE cmd+v posted ok=true         # 进程内 CGEvent(core-graphics 0.25)
SKIP self-write changeCount=108
```

目标应用实测收到 `TEXT=[CHAIN-PASTE-OK]`，整链（捕获 → 写回 → ⌘V → 目标应用）成立。

## 六、权限

- 合成按键 / CGEvent 需要辅助功能授权，未授权时 `AXIsProcessTrusted() = false`，`osascript key code` 报错 `1002`
- 授权后 `axTrusted=true`，进程内 `CGEvent` 可正常发送
- 引导入口可用：`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility`

## 九、P2 面板（2026-11-15 下午，clipnest 产品化第一版）

面板 = 搜索框 + 历史列表 + 键盘操作（↑↓ 选择、⏎ 粘贴、Esc 收起）。

### 9.1 键盘链路的三个必要条件（缺一个就打不了字）

| 条件 | 依据 | 不做会怎样 |
| --- | --- | --- |
| 窗口 `activate = Some(true)` | `NSApp.active=true` 才有 key window | `key=None active=false`，按键全被前台应用吃掉 |
| `focus()` 从**主线程**发出 | `set_timeout` 回调里 `MainThreadMarker::new() == None`；非主线程调 AppKit 是空操作 | 日志 `PANEL focus try=N key=None active=false`，重试到放弃 |
| 输入框 `auto_focus(true)` | 输入框在窗口隐藏时渲染，靠它拿 field editor | 窗口成 key 但字符进不了 `input().on_change` |

实测成功的日志：

```
FRONT remember pid=699                     # 打开面板前记下前台应用
PANEL focus try=0 key=Some("") active=true # 窗口成了 key
SEARCH q="hello" rows=1                    # 字符进到了搜索框
```

进不去键盘的原因顺序排查（都是实测过的坑）：

1. `PANEL focus try=N key=None active=false` → 没 `activate`，或 `focus()` 不在主线程
2. `key=Some(...) active=true` 但仍无字符 → `input` 没拿到 field editor（`auto_focus` 缺失 / 被后来的 `focus()` 打断）
3. 手动再 `focus()` 一次输入框反而**丢输入**（field editor 重挂），别画蛇添足

### 9.2 焦点在输入框里时的按键归属

- **Esc 被 `input` 吃掉**，`WindowKind::Popup` 自带的 `close_on_escape` 收不到。要自己绑 `on_key_with("escape", When::Always, || dismiss())`。
- 方向键同理：单行 `input` 会消费 ↑↓，必须 `When::Always`（`KeyOptions { when: Always, repeat: true, pass_through: false }`）。
- ⏎ 用 `input().on_submit(...)` 就够（`on_key("enter")` 在输入框聚焦时不会触发，别双绑以免粘两次）。

### 9.3 粘贴：面板会抢走前台，必须切回去

打开面板（`activate=true`）后前台应用变成 clipnest。所以粘贴是四步：

```
写回剪贴板 → dismiss()（隐藏面板 + activate 原应用）→ 120 ms → CGEvent ⌘V
```

- 原应用 pid 由 `NSWorkspace::sharedWorkspace().frontmostApplication()` 在**打开面板之前**记下（`clipboard::remember_front_app`）
- ⌘V 必须等切回生效后再发（沿用 P0 的 120 ms）
- 放弃（Esc / 失焦）也走 `dismiss()` 的切回逻辑，否则用户被留在面板里
- 回环抑制照旧：写回后登记 changeCount，watcher 见到 `SKIP self-write`

端到端实测（前台是 `tools/paste_target.swift`）：

```
SEARCH q="hello" rows=1
PASTE id=2 kind=text cc=142
FRONT activate pid=699 ok=true
SKIP self-write changeCount=142
AUTOPASTE cmd+v posted ok=true
目标窗口收到 TEXT=[面板测试 第二条 hello]
```

### 9.4 其它实现坑

- **列表必须包 `dynamic(|| ...)`**：`view().children(items.iter().map(...))` 是静态快照，搜索后列表不刷新（底部那行计数是响应式的，会显示 1/N 而列表还是首帧，极易误判）。
- **`#[component] fn Panel()` 的构造器是小写 `panel()`**，不是 `Panel()`（宏生成 `PanelElement` + `panel()`）。
- 每次打开面板要清空查询并重查：面板窗口是「隐藏/显示」而非重建，组件的 signal 会留着上次的搜索词。
- nsh 的 `run_app` 总会开一个主窗口：常驻应用要在根组件里 `current_window().hide()` 掉（`MAIN window hidden id=main main=true`）。
- 合成打字（`tools/keys3.swift type:...`）每个字符必须**新建** `CGEvent` 并用 `.combinedSessionState`；复用/`.hidSystemState` 时字符不进输入框（同一次会话里 `x` 能进、`hello` 不能）。

## 十、托盘与设置窗（P2 后半）

### 10.1 托盘

```rust
tray().icon(ImageSrc::svg_markup(SVG)).tooltip("…").title([TrayTitleRun::new("❐")])
      .menu(vec![MenuItem::new("显示面板").on_select(..), MenuItem::new("偏好设置…").on_select(..),
                 MenuItem::separator(), MenuItem::new("退出 clipnest").on_select(..)])
      .on_click(move |_| toggle())
```

实测：

```
TRAY attached
# 点菜单栏 ❐：System Events 报 "menu bar item ❐ of menu bar 2 of application process nsh-app-clipnest"
PANEL toggle before=false after=true
PANEL rows=2
```

坑：

- **菜单栏里 16 pt 的纯图标很难确认也没法自动化点**，所以配一个 `title` 字符（`❐`）——`System Events` 能按名字找到它，也能直接报坐标。
- `on_click` / `on_select` 的回调线程不确定，回调里只能碰 `static`（见 10.3）。
- 图标用内联 SVG：macOS 当模板图，笔画颜色用 `black`，只认不透明度（用其它颜色会变实心/不可见）。

### 10.2 设置窗（`WindowKind::Dialog`）

540×340，`input` 直接绑设置字段，改一项存一项（`settings.json` 原子写：先 `.tmp` 再 rename）。

实测：

```bash
echo '{"max_items":1,"panel_height":420}' > $CLIPNEST_DATA_DIR/settings.json
# 启动
PRUNE startup removed=1 max=1          # 启动补给：按上限裁到 1 条
# 面板高度改 600 后重启，窗口 bounds 实测 Height=600
```

坑：

- 坏 json / 缺字段要用默认值兜底（`#[serde(default)]` + 解析失败记日志），否则用户手改坏一次应用就起不来。
- 受控 `input`（`.value()` 绑 signal）在 `on_change` 里必须同时更新那个 signal，否则输入被回滚到旧值。
- 窗口尺寸在创建时给，改设置只能「下次启动生效」——UI 上要写明，不然像 bug。

### 10.3 跨线程：`Signal` 要放 `static`

`set_timeout` / 托盘菜单的回调可能不在主线程，而 `thread_local!` 是「每线程一份」：
把面板 `open` 信号放 thread_local 时，从定时器里读到的永远是 `None`（设置窗根本打不开）。

结论：`static OPEN: OnceLock<Signal<bool>>`（`Signal` 是 `Copy + Send + Sync`），
`thread_local` 只留真正与 UI 线程绑定的东西（`WindowRef`、`ElementRef`）。

## 十一、条目动作（P2 收尾）

键位与实测（面板内，焦点在搜索框里也生效，全部 `When::Always`）：

| 键 | 动作 | 实测日志 |
| --- | --- | --- |
| `⌘1`–`⌘9` | 直接粘贴第 N 条 | `PASTE id=1 kind=text` → `FRONT activate pid=… ok=true` → 目标收到 `TEXT=[测试 动作A]` |
| `⌘D` | 删除当前条 | `DELETE id=4` |
| `⌘P` | 置顶切换（`update_meta`，不动 `updated_at`） | `PIN id=4 -> true` |
| `⌘S` | 收藏切换 | `FAV id=4 -> true` |
| `⌘Y` | 复制到剪贴板但不粘贴 | `COPY id=4 cc=160` |
| `↑`/`↓`/`⏎`/`Esc` | 选择 / 粘贴 / 收起 | 见第九节 |

### 11.1 三个必须记住的坑

1. **`⌘⇧C` 这类 shift 组合到不了 keymap**：`on_key_with("mod+shift+c", When::Always, …)` 不触发（`osascript` 与进程内 CGEvent 都试过），而 `⌘P`/`⌘S`/`⌘D`/`⌘Y` 全部正常。复制改用 `⌘Y`（yank）。
2. **`close_on_blur` 会把面板自己关掉**：删条目/置顶后 rows 变化 → 重渲染 → 搜索框的 field editor 重挂 → 窗口收到 blur → 面板关闭（日志 `PANEL open=false reason=Blur`，前台还是自己）。现在 `close_on_blur = Some(false)`，只认 Esc；`SPIKE_CLOSE_ON_BLUR=1` 可以切回旧行为对照。
3. **主窗口不能 `hide()`**：主窗口一隐藏，应用就不算 active，面板永远成不了 key window（`key=None active=false`，键盘全被前台应用吃掉）。改成「去掉标题栏 + 透明 + 挪到屏幕外 + 点击穿透」——系统最多只让窗口移出到 `x=-380`（还留 40pt），所以透明和 `pointer_events: None` 是必须的。

### 11.2 列表要用 `each`

- 静态 `children(...)`：不刷新（底部响应式计数正常，最容易被骗）。
- `dynamic(|| …)`：能刷新，但整块重建，删一条就触发上面第 2 条的失焦关窗。
- `each(rows, |r| r.id, |row, i| …)`：按 key 只增删变化的那一行，删除后焦点还在搜索框。

附带一个 Rust 细节：行渲染函数要返回具体类型 `View` 而不是 `impl IntoElement`，否则在 `each` 的闭包里返回会把 `&Row` 的生命周期带出去（E0515）。

## 九、Windows 交叉编译（2026-11-15 补测）

原判断「macOS 无法交叉编译」已被推翻。环境：卸载 brew rust → 官方 rustup → `rustup target add x86_64-pc-windows-msvc` → `cargo install cargo-xwin`（0.23.1）。

| 步骤 | 结果 |
| --- | --- |
| `cargo xwin check --target x86_64-pc-windows-msvc` | ✅ 全仓通过 |
| `cargo xwin build --release --target x86_64-pc-windows-msvc` | ✅ 1m48s；`nsh-app-clipnest.exe` 43 MB，PE32+ GUI x86-64 |
| `nsh package --target windows` | ✅ 2m5s；`.nsh/out/clipnest.zip` 20 MB + `.nsh/out/clipnest/`（exe + nsh/app.json） |
| Inno Setup 安装包 | ⚠️ 只生成了 `clipnest.iss`，打 `.exe` 安装包需 Windows 侧装 Inno Setup 6 |

导入表（`llvm-objdump -p`）：`d2d1.dll`、`dwrite.dll`、`d3d11.dll`、`dxgi.dll`、`dcomp.dll`、`dwmapi.dll`、`comctl32.dll`、`bcrypt.dll`、`api-ms-win-crt-*`
→ 确认 Windows 后端是 Win32 + Direct2D/DirectWrite，UCRT 用系统自带（Win10+ 无需 VC 运行库）。

### Windows 后端的 API 差异（本次编译暴露）

`nsh-platform-windows 0.5.1` 的 `AppOptions` 只有 12 个字段，缺 macOS 有的：

- `keep_alive_on_close`（关窗常驻）
- `activation_policy`（accessory 菜单栏形态）
- `background`（`NSApplicationActivationPolicyProhibited` 等价物）
- `display` / `keep_size` / `chunks` / `host` / `limits`

已处理：`src/main.rs` 里这些字段用 `#[cfg(target_os = "macos")]` 门控（原先直接写在结构体里导致 Windows 编译失败）。
**含义**：Windows 上的「托盘常驻 + 不抢焦点」形态不能照搬 macOS，必须在真机验证，属于路线图 R1 的新增子风险。

### 结论

编译与打包不再是 Windows 侧的阻塞项：Mac 出 zip → 拷到 Windows 解压双击即可冒烟，无需在 Windows 装 Rust/VS/nsh。
仍必须真机验证的：Popup 是否抢焦、`RegisterHotKey` 触发、剪贴板事件驱动路径、`SendInput` 粘贴、托盘图标、多显示器定位。

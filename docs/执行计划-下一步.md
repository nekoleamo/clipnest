### T2 ✅ schema 与迁移（对齐行为契约）

草案（细节按契约 1–6 调整）：

```sql
CREATE TABLE IF NOT EXISTS items (
  id            INTEGER PRIMARY KEY,
  content_hash  TEXT NOT NULL UNIQUE,   -- blake3("<kind>:<content>")
  kind          TEXT NOT NULL,          -- text | html | rtf | image | files
  content       TEXT NOT NULL,          -- 文本原文 / 图片文件名 / 换行路径
  file_types    TEXT,                   -- 'd/f' 串，仅 files
  width         INTEGER, height INTEGER,-- 仅 image
  use_count     INTEGER NOT NULL DEFAULT 1,
  pinned        INTEGER NOT NULL DEFAULT 0,
  favorite      INTEGER NOT NULL DEFAULT 0,
  note          TEXT,
  group_id      INTEGER REFERENCES groups(id),
  sensitive     INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS groups (id INTEGER PRIMARY KEY, name TEXT NOT NULL UNIQUE, sort INTEGER);
CREATE VIRTUAL TABLE IF NOT EXISTS items_fts USING fts5(
  content, note, content='items', content_rowid='id', tokenize='trigram'
);
-- 触发器保持 items_fts 与 items 同步（insert/update/delete）
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT);  -- schema_version 等
```

要点：
- 迁移用 `user_version`（`PRAGMA user_version`）递增，不用外部 migration 框架
- `tokenize='trigram'` 支持中文与子串搜索；契约 7 的「短词降级 LIKE」在查询层实现

**验收**：测试覆盖建库、重复打开、版本号推进、FTS 与触发器同步（增/改/删各一条）。

## 7. P1 完成记录（2026-11-15，实现与计划的差异）

代码落点（与计划的偏差已标出）：

| 计划 | 实际 | 说明 |
| --- | --- | --- |
| `src/db/{mod,schema,items,search}.rs` | 同 | `db::open` 里顺带跑迁移、设 WAL / `foreign_keys` / `busy_timeout(5s)` |
| `src/model.rs` | 同 | 另含 `NewItem` 构造器、`Item::excerpt()`、`now()` |
| `src/backup.rs` | 同 | 加密原语 `chacha20poly1305 0.11` + `argon2 0.6`（`cargo add` 拉到的版本，API 与 0.10/0.5 不同） |
| 计划未列 | **新增 `src/paths.rs`、`src/store.rs`** | 交付目录布局与采集接线；`lib.rs` 按 AGENTS 约定只留组件 + UI（多出来的 `store_capture()` 是唯一非 UI 函数） |
| `mod model` | `pub mod model` | 私有模块里的 `pub` 项会触发 dead_code 警告 |

实现选择：

- **FTS5 trigram 的门槛按字符算**：查询词 ≥3 个字符才走 FTS，2 个汉字（如「银河」）命中不了，必须降级 `LIKE`（已测）。这也是契约 7 的落地方式，阈值常量 `db::search::FTS_MIN_CHARS`。
- FTS 查询把用户输入包成**短语**（内部 `"` 翻倍），`-` `*` `(` 之类不会被当语法，也不需要拼 `MATCH` 表达式。
- 导入语义是「补齐」：同 `content_hash` 已存在就跳过（`DO NOTHING`），不覆盖本地改过的收藏/备注，重复导入天然幂等。分组按**名字**对齐，不照搬 id。
- `use_count` / 时间戳在导入时逐字段还原（不是走 `upsert`），所以 round-trip 完全一致。
- `uuid` 用来给每个库写一个 `meta.install_id`（P4 同步的设备身份），否则该依赖一直空转。
- 数据根目录：macOS `~/Library/Application Support/clipnest`、Windows `%APPDATA%\clipnest`、Linux `$XDG_DATA_HOME/clipnest`；`CLIPNEST_DATA_DIR` 可整体覆盖（实测跑测试用）。
- 图片资源分片在第一层：`images/origin/<hash前2位>/<hash>.png`，`items.content` 只存 `<hash>.png`。
